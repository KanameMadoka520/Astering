# 账户隔离与站点用量

Astering 支持同一实例中的多个账户，通过项目用户／团队共享进行协作。它不是为每个组织分配独立数据库、独立加密主密钥和独立运维管理员的 SaaS 租户系统；操作系统与部署管理员仍属于受信任边界。

## 阿罗娜的权限

| 内容 | 使用范围 |
|---|---|
| 模型与语音设置、密钥 | 当前账户独立加密保存；读取接口不返回密钥。 |
| 会话、运行、审核与附件 | 绑定账户和会话；不能通过别人的 ID 获得访问权。 |
| 外部 MCP | 只使用当前账户保存且本轮选中的连接；连接开关、修订、凭据目的地与审核持续校验。 |
| 项目与任务 | 本人拥有，或明确共享给本人／所属团队；只读共享不能写入。 |
| 星图 | 保留空间权限和独立工具模块开关；不会因模型猜到 ID 而授权。 |
| 网盘 | 个人原件按所有者隔离；共享任务附件遵循任务权限，不转移个人网盘所有权。 |

模型不是授权主体。执行层同时约束工具模块、读写模式、项目范围、账户业务权限和操作审核。阿罗娜内部 HTTP 转发与直接数据库工具均携带可信的“仅资源权限”范围：即使用户在已启用的实例管理功能中拥有额外权限，助手也不能借此绕过未共享项目的 ACL。原账户的普通管理界面行为不变；该标记不进入数据库、JSON 或 JWT，也没有可由外部设置的请求头。

审核期间撤销共享后，批准旧计划也不能执行新的无权修改。不同账户的配置、会话和 MCP 凭据不自动共享。外部 MCP 服务究竟允许访问哪些远端数据，仍取决于当前用户给该服务配置的凭据和远端 ACL，不能由 Astering 代替远端授权。

撤销项目共享会阻止新的源资源访问；不会追溯擦除用户此前已经获得并保存的个人对话快照。需要追溯删除时，应另行制定数据保留规则，不能静默清除历史。

权限设计遵循服务端逐次授权与默认拒绝原则，参考 [OWASP Authorization Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html) 与 [Multi-Tenant Security Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Multi_Tenant_Security_Cheat_Sheet.html)。这些参考不等于独立安全认证。

## Astering 超级管理员与账户运维

部署者通过 **`ASTERING_SUPERADMIN_IDS`** 单独指定受信任账户 ID（逗号分隔）。实际部署必须先核对真人账户，不能按昵称自动认定，也不能照抄文档示例。未设置或显式空值不授予任何账户该能力。此配置不修改 `users.is_admin`，不继承 `ASTERING_USAGE_ADMIN_IDS`、SMTP 管理员或上游许可角色；原有许可检查保持原样。

超级管理员页面是 **设置 → 站点 → 账户管理**（`/user/settings/accounts`）。它与只读的站点用量页共用统计展示，管理授权彼此独立。站点用量权限不会因为能够管理账户而自动授予，反之亦然。页面提供：

- 分页搜索和筛选账户状态、账户类型、项目数量、归属存储等运营指标。统计不授予私有项目、网盘、会话、模型或 MCP 凭据的内容访问权。
- 查看账户及其直属机器人保存的会话记录和 API 令牌**数量**；数量不等于当前在线设备数，也不展示实际凭据。
- 将正常的普通真人账户停用，或将已停用的普通真人账户恢复。验证中的账户不能通过此入口跳过验证，安全锁定的账户不能通过此入口绕过解锁流程。
- 撤销普通账户及其直属机器人的现存登录会话、API 令牌及尚未使用的 OAuth 授权码，并停止该账户的阿罗娜运行和压缩。
- 查看分页的操作记录，包括操作者、目标账户、动作、原/新状态、实际撤销量、可选简短原因和时间。记录不存邮件、IP、密码、令牌、模型配置或业务正文；原因应填写运维说明，不能填写密钥。

**当前账户、全部配置中的超级管理员、机器人账户以及已排期删除的账户都受保护，不能在此入口操作。** 需要管理自己的设备时使用登录设备页；超级管理员授权由部署配置维护，不提供网页内提升权限。此入口不创建账户、不改密码、不修改上游管理员角色、不永久删除用户，也不接管业务资源。

标记为上游实例管理员（`users.is_admin=true`）的账户也不能通过此入口变更状态；它的状态管理仍归原有许可管理入口，相关许可检查不变。这里仅允许撤销其现有凭据。这样不会由另一套独立运维授权并发停用全部上游管理员。

操作必须输入目标账户的完整当前用户名确认；停用/恢复还绑定确认时的状态。服务端在统一身份锁之后重查操作者授权、目标身份、保护范围和原状态，过期确认返回冲突，不能靠前端按钮隐藏保证安全。状态/凭据修改与 `account_admin_events` 审计插入在同一事务提交；失败时不写成功记录，不取消别人的后台任务。审计不随目标或操作者删除级联清除。

停用会阻止新的真人登录、会话刷新、API 令牌及机器人身份认证。停用与恢复都会在同一事务中撤销目标账户及其直属机器人的现存会话、API 令牌和 OAuth 授权码；旧版本或 CLI 停用时残留的凭据也不会因为恢复而重新生效。撤销后已有 JWT 的签名即使尚未过期，也因对应会话失效而不能继续发起授权操作。凭据签发会在用户锁之后重查身份状态及原认证会话/令牌；已经通过请求入口鉴权的旧请求不能等待注销完成后再创建新令牌或机器人。OAuth 授权码消费与后续签发之间还绑定撤销代次，避免已经取出的旧授权码在注销后重新获得会话。恢复账户不复活旧凭据、不自动恢复已停止任务；正常账户可以重新登录。

阿罗娜的取消在事务提交后执行，覆盖所有活跃会话、压缩和继承父运行的子任务。后台任务也定期核对账号状态；停用只停止执行，保留对话、网盘原件及业务数据，不会触发“账户删除”的永久清理。外部模型/MCP 是否已经提交远端操作仍以远端实际状态为准，取消不能倒回已经完成的修改。

账户停用和凭据撤销**不会修改项目成员、团队共享及已创建的公开链接**。这些是独立授权对象；公开分享、公开日程仍遵循各自开关和访问规则。需要停止公开访问时应单独撤销相应分享；恢复账户也不会恢复已经撤销的共享。停用不是整个组织、项目或所有分享的紧急封锁功能。

待验证用户的默认收件箱初始化，以及已停用账户的删除清理，使用仅限内部事务和对应账户的维护范围。该范围只允许必要的非活跃账户生命周期操作，仍检查资源归属和共享权限；结束或出错立即清除。浏览器会话、API Token 和阿罗娜身份不能继承这一范围。

管理路由仅接收活跃的真人浏览器会话；API 令牌、机器人、公开分享及阿罗娜的可信资源范围身份都被拒绝，即使它们对应的账户在超级管理员列表中。它们不加入阿罗娜工具目录或 MCP 操作白名单：助手无法借“管理账户”绕过原有业务权限。

阿罗娜生成、重试/审核继续及压缩在注册后台任务前，会重新验证原会话凭据，并用同一运行锁保护的撤销代次封住“校验通过但尚未注册”的窗口。旧同步工具循环也登记短期取消槽。撤销提交后，先注册的任务会取消，后注册的旧请求会拒绝；后台结束仍可保存停止状态，不会把停用误当成删除或重启任务。此代次不包含正文或密钥，在当前进程内从不清零复用。

**当前部署按单个应用进程设计。** 即时运行取消和任务准入代次在该进程内协调；仅共享数据库并不能保证多个副本同步停止运行。未来部署多个应用副本时，必须补齐共享撤销通知和代次存储，才能提供同样的跨副本即时取消保证。账户状态和资源权限仍逐次检查，不能将当前实现解释为已支持完整的多副本运行调度。

运行中的账户状态读取只查询身份、状态和机器人归属。遇到明确的 SQLite 临时读锁时，在单次总超时内使用新会话短暂重读；不缓存身份、不重放写操作，也不重试其他错误。解锁后仍须读取并遵循最新停用或删除状态。PostgreSQL 不经过这段 SQLite 重试。

| 路由 | 功能 |
|---|---|
| `GET /api/v2/system/accounts/access` | 当前真人的账户管理能力。 |
| `GET /api/v2/system/accounts` | 运营用量、当前管理控制和凭据数量。 |
| `POST /api/v2/system/accounts/{id}/status` | 绑定用户名和预期状态的停用/恢复。 |
| `POST /api/v2/system/accounts/{id}/revoke-access` | 撤销现存凭据并停止阿罗娜运行。 |
| `GET /api/v2/system/accounts/events` | 分页的操作审计，可按目标 ID 筛选。 |

账户管理的业务 JSON 使用 `no-store`。基础用量沿用最多 30 秒的有界快照；页面管理标志、目标状态、保存凭据数量逐次重读。管理员操作提交会使用量快照失效，旧的后台采集不能重新填充旧缓存。外部 CLI/直接数据库变更的统计筛选仍可能在 30 秒内更新；执行操作始终重新授权，不使用快照作安全判断。

## 独立、只读的站点用量

部署者通过 `ASTERING_USAGE_ADMIN_IDS` 配置允许查看用量的账户 ID，以逗号分隔。例如 `2,5`。未设置、空值或移除 ID 均不授予权限；不会继承 SMTP 配置管理或实例管理员角色。实际部署应核对账户 ID，不能照抄示例给未知账户授权。

仅已认证、状态正常的真人会话可以使用；API Token、机器人、待验证、禁用、锁定和已删除账户被拒绝。服务端每次请求重新核对身份与授权，前端入口隐藏不是安全边界。接口为：

- `GET /api/v2/system/usage/access`：当前账户是否能查看。
- `GET /api/v2/system/usage/users`：分页、搜索、状态／角色／数量提示筛选及排序的统计快照。
- 页面：`/user/settings/usage`，位于设置的站点分组。

这项 Astering 原创运行观察能力不改变上游许可开关，不提供账户创建、改密码、提升权限、封禁、删除、原文或凭据访问，也不进入阿罗娜工具目录。

## 统计口径

项目按**当前所有者**归属，包含归档；近期 24 小时／7 天数量按创建时间及当前所有者计算，不能解释为最初创建者。任务分别统计“拥有项目中的非软删任务”与“由此账户创建的非软删任务”，两者不相加。

文件按原件 ID 去重，使用数据库记录的逻辑原件长度，包含尚保留的回收站文件。网盘及回收站是子集，不再次相加；同原件多次引用只计一份。AI 会话、旧独立附件、模型与 MCP 配置只读取规范加密文件的元数据，不解密。新网盘附件已在原件中统计，不重复加入 AI 附件。

“归属存储”＝上传原件逻辑大小＋独立 AI 密文文件长度。它不等于服务器磁盘实际分配，不含预览、数据库／索引／WAL、备份、临时与孤立文件。概览仅覆盖已持久化账户的归属，匿名／分享链接上传不强行归给某个用户。星图按空间所有者归属，含团队空间、归档与回收站条目，不授予正文访问权。

快照最多缓存 30 秒，从采集开始计时；SQL 分组采集避免每个账户单独查询。文件系统扫描有总预算与取消检查，不递归读取业务内容；不完整值显示为已知下限，不能当作确定零。刷新失败或权限被拒绝时隐藏旧私有快照。采集可能与写入同时发生，不能作为停写一致性备份。

提示阈值为拥有至少 1,000 个项目，或近期 24 小时创建且仍拥有至少 100 个项目，或 7 天至少 500 个项目。只提示人工核查，不证明滥用，不自动限制或修改用户。

## 管理界面的加载与确认

账户操作以服务器写入回执为准；后续列表、审计或用量刷新独立进行，不因慢读一直锁住确认弹窗。刷新期间不展示旧账户操作入口。确认失败保留输入与焦点；普通权限复查保持已打开的草稿，但等待复查时不允许提交。首次进入必须收到本次授权响应。受保护列表或审计明确返回 403 时，撤下本页管理授权，同时清除确认框、回执及审计内容；旧身份的迟到拒绝不得影响新身份。

审计换页时保持分页按钮和焦点，仅保留同身份的分页数字，不把旧审计正文当作新页内容。操作回执关闭弹窗后，优先回到仍存在的原入口；列表暂未返回时回到搜索框，不等慢读且不在读完后再次抢焦点。

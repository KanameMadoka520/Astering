# 关键路径检修（aster.40）

本次围绕异步操作的归属、会话状态的新旧顺序以及模型 HTTP 连接的生命周期检修。修复以可复现的问题为边界，不引入新的依赖、数据库迁移、接口协议或全站状态框架。

## 删除确认与页面归属

任务删除确认固定打开时的任务和请求身份。切换任务、账户或 API 后，旧确认不能删除当前页面里的另一条任务。删除发出后可以继续浏览；成功响应只有在原组件、路由和确认目标都仍有效时才能关闭弹窗或导航。失败保留重试入口。

项目删除确认同样记录打开时的账户、认证会话和 API。即使另一账户或另一 API 恰好有相同项目 ID，也不能沿用旧确认；同一账户正常刷新访问令牌不应误判为更换账户。服务端仍独立检查项目权限，前端确认保护不替代服务端授权。

慢速删除期间离开并重新进入任务，后打开的详情也必须收到删除结果。移除查询缓存前，先通知已挂载的任务观察者并记录删除状态，避免观察者继续持有旧查询、显示已经不存在的可编辑任务。普通删除与阿罗娜删除回执共用这一入口，移动任务仍走原有集合更新路径。

## 会话快照的新旧顺序

阿罗娜同时接收完整 HTTP 会话和流式活动。旧 HTTP 查询或操作确认可能晚于流式进度返回，不能把刚刚完成的状态覆盖为较早的运行状态。初次加载时，流式活动也可能先于完整会话到达；合并必须等待完整元信息，不能用一段活动伪造会话。

保护只处理实际交错的更新。之后正常发起的查询仍可以采纳服务器的新状态，不能简单按“完成优先”或客户端时间戳永久屏蔽后续操作。缓存生命周期继续按账户、API 和认证会话隔离。

查询在实际缓存提交时协调快照，覆盖请求返回到缓存提交之间的微任务间隙。成功写入与普通查询分别处理，避免先返回的旧查询阻止发送确认里的新增消息；交错的成功响应保留各自新增的消息。协调器只临时保留尚未结束请求期间的最新活动引用，不为每个文字片段保存一份历史快照。

## 流式完成与连接回收

OpenAI Chat 的 `[DONE]`、Anthropic 的 `message_stop` 和 Responses 的完成或不完整终态是明确的协议结束事件。收到后结束解析并关闭响应体，不再额外等代理或上游断开连接。OpenAI 的 `finish_reason` 仍允许后续用量帧，Gemini 的 `finishReason` 仍沿用读取后续帧的行为，避免漏掉用量。

一次 agent 执行拥有一个私有 HTTP 连接池，多轮模型调用和嵌套子代理共享连接池，在 HTTP 响应允许时复用 TCP/TLS 连接。子代理不关闭父任务的池；最外层任务结束后回收空闲连接。模型列表、连接测试等单次调用自行回收，避免不可再使用的 transport 留下空闲连接。密钥继续逐请求设置，不进入全局连接缓存。

现有 SSRF 安全拨号、代理策略、禁止跟随重定向以及调用者上下文取消保持有效。连接池只在一次执行内共享，不跨独立任务保存；每个新执行读取当前出站配置。

明确终态后及时关闭流优先于等待 HTTP 尾部结束。HTTP/1.1 的响应如果还有未消费的分块或尾部，底层可能放弃该连接；不承诺每一轮 SSE 都复用同一条连接，也不额外加入后台排空或隐藏等待。实际 agent 的连接复用回归使用完整读取到 EOF 的非流式响应验证。

## 验证与范围

浏览器缓存按内容版本和权限拆分，具体规则见[浏览器缓存与私人图片](browser-cache.md)。带内容哈希的静态资源长期复用，固定入口重验证；私人图片在检查当前权限后才允许 304，非图片下载、业务 JSON 与实时事件继续不持久缓存。预览验证器包含文件身份、尺寸及编码版本，避免不同预览互相命中。

Service Worker 使用同一套路由模块处理实时入口、API 和有限构建预缓存，避免两套路由各自注册 `fetch` 监听器。移除无容量约束的扩展名运行时缓存，并且只清理本应用遗留缓存。

回归测试先在修复前运行，确认能复现实际问题，再检查修复后的行为。竞争条件使用真实 QueryClient 和可控请求；模型连接使用本地真实 HTTP 服务，分别观察协议终止、连接复用、取消和连接关闭。可见删除交互另外通过隔离数据库的浏览器测试验证，生产检查保持只读。

本机最终前端全量回归为 349 个文件、3,775 项通过、1 项已有的可选测试跳过。真实 Workbox 路由补验 9 项通过。浏览器覆盖 5 个 spec 的 63 个场景；首轮发现慢速删除观察者缺陷，以及两处测试夹具与 API、事件协议不一致，修复后定向重跑相关 8 个场景，全部通过。未通过的首轮记录保留，不用重跑后的结果覆盖原日志。

后端验证覆盖流式终态、尾部用量、连接生命周期、SSRF 和重定向约束，以及静态与私人媒体的缓存、权限、删除、预览尺寸、Range 和非图片下载。前端客户端通过 Mage 重新生成并通过可重复生成检查。生产验收另核对公网与源站版本和入口资源一致、业务数据与加密模型配置未变、只读桌面及移动布局、真实浏览器的 HTTP 缓存和 Service Worker 实际缓存内容。

这些结果用于确认本次修复和相关边界，不代表对整个代码库作出无漏洞或所有页面性能提升的保证。没有把合成连接数量、单元测试时间或本机浏览器结果当成真实用户的网络延迟、INP 或模型吞吐速度。

# 看板分组：按上级任务整理大型多阶段项目

看板列标题旁的「卡片 | 分组」切换只改变**显示方式**。两种方式读同一份看板数据，不改动任务关系、位置、颜色、完成状态或所在列，也不增加请求。

- **卡片**（默认）：原有看板，可拖动排序、跨列拖动、拖入侧栏项目。
- **分组**：每一列内按上级任务分组，卡片变为紧凑行。适合「总目标 → 阶段 → 步骤」这类层级很深、单列很长的项目。

选择按账户（或链接分享）+ 服务器 + 项目 + 视图记在本机，最多保留 40 个视图、每个视图 400 个折叠状态；退出登录会清空。切换不改变路由。

## 参考与取舍

- Linear 看板可按上级 issue 分组与子分组：[Display options](https://linear.app/docs/display-options)；上下级概念见 [Parent and sub-issues](https://linear.app/docs/parent-and-sub-issues)。
- Jira 可按上级任务划分泳道，子任务在泳道内按状态分列：[Configure swimlanes](https://support.atlassian.com/jira-software-cloud/docs/configure-swimlanes/)。

两者都是**全局泳道**：每个上级占一行，横跨所有列。这里改为**列内分组 + 聚焦**，原因是：

- 看板的列常是自定义类别（如制作、审核、发布），不是统一的状态流，子任务常与上级不在同一列。「阶段 × 列」的泳道矩阵大部分格子为空；390px 手机一次只看一列，泳道还会把这一列切成更多段。
- 每列单独分页（每页 25 张）。泳道要知道每个上级在每一列的全部子任务才不误导；列内分组只用已加载的卡片，并明确标出已加载数和「加载更多」。
- 筛选型看板里同一张卡片可以出现在多列，泳道行的归属无法唯一确定。
- 想看「一个阶段在所有列的情况」时用聚焦：列不变，只留下该任务及其下级。原有的列、拖动和数据模型都不变。

## 分组规则

- 每张已加载卡片在**它所在的列**里恰好出现一次。筛选型（动态）看板的一列一列是独立查询，同一任务可以同时出现在多列，每列各显示一次。
- 卡片挂在它的「显示上级」下面。显示上级只有一个：按任务编号从小到大选第一个不会形成循环的上级。有多个上级时，行内用「+N」注明其余上级；循环关系只为显示而断开，关系本身不变。
- 上级卡片也在本列时，它就是分组标题（真实任务，可完成、移动、打开）。
- 上级不在本列（在别的列、在后续页、被筛选掉或属于其他项目）时，本列内同一上级的多张卡片收在一个**上级参考**标题下。上级参考标题带虚线「上级参考」标记并说明上级卡片在哪一列，或「不在已加载的卡片中」。上级参考标题只来自已加载卡片附带的关系摘要，不会为了显示标题去额外读取任务，也不会把未匹配筛选的上级当作卡片显示。
- 只有一张卡片时不建上级参考标题，改在该行显示上级路径（如「总目标 › 第三阶段」）。
- 分组出现在其第一张卡片原本的位置，组内保持列内原顺序；不按标题或进度重排。
- 层级缩进最多两级，更深的层级保留引导线但不再缩进。标题不截断，完整换行。

## 进度口径

| 显示 | 含义 |
|---|---|
| `2/8`、「直属子任务已完成 2/8」 | 上级卡片已加载时，它的全部**直属子任务**（你有权限看到的、所有列）中已完成的数量。不受筛选和分页影响。 |
| 「进度未知」 | 上级只出现在子任务的关系摘要里，没有它的完整子任务列表，不做推测。 |
| 「本列 N 张」 | 该组在本列已加载的卡片数。折叠后仍显示，不会悄悄藏起卡片。 |
| 「已加载 25/35」+「加载更多」 | 该列匹配数与已加载数。滚动加载照常可用，折叠后也能用按钮加载。 |

- 只统计直属子任务，不跨层累计（总目标显示阶段完成数，而不是全部步骤）。
- 描述里的清单（复选框）是另一种进度，仍以原有清单标记单独显示，不计入子任务进度。
- 完成全部子任务不会自动完成上级任务。

## 操作

- **完成**：行首复选框，与卡片的 Ctrl/⌘ 点击相同：日常任务改为今日打卡；完成循环任务会提醒看板重新读取日期筛选；完成列会接收完成的任务。是否可勾选按任务所属项目的权限判断（收藏、已保存筛选会混合多个项目），与列是否为手动列无关。保存失败时勾选状态保持原样。
- **移动**：分组视图没有拖动。分组顺序是显示顺序，拖到两行之间无法唯一对应真实位置（中间可能隔着折叠、未加载或其他组的卡片），所以改用每行的「移到其他列」原生选择框：已满的列不可选，完成列注明「会标记为完成」，日常任务不会移入完成列。移动保留任务原有位置值；需要调整顺序请切换到「卡片」拖动。只有手动列且有写权限时提供移动；筛选型列由筛选决定归属。
- **聚焦**：有子任务的行和上级参考标题上的准星按钮。聚焦只显示该任务及其全部下级（按真实关系，包括另有其他上级的子任务，循环安全），列和数据不变。顶部聚焦栏给出上级路径、直属进度、已显示/已加载数量，并在可展开的列表里列出不在已加载卡片中的直属子任务（最多列 12 个名称，其余计数）。每列注明「N 张已加载卡片不在聚焦范围内」；有未加载页时提供「每列再加载一页」。Esc（焦点不在输入框、选择框、菜单或对话框中时）或「显示全部卡片」退出，焦点回到原来的聚焦按钮。
- **折叠**：分组标题的展开按钮支持键盘；工具栏可一次展开或收起全部分组。折叠状态按「列 + 上级任务编号」记录，所以上级卡片随下一页加载出现后，原来收起的组仍保持收起。搜索或筛选时分组一律先展开，期间的折叠只在本次结果中有效，结束搜索后恢复原来的折叠状态。

## 可访问性与手机

展开按钮使用 `aria-expanded`/`aria-controls`，完成标记是带名称的复选框，移动框有逐任务的名称，上级参考与路径有屏幕阅读器文字。触屏设备上的按钮不小于 44px。390px 宽度下列仍按原方式横向切换，页面不出现横向滚动。没有布局动画。任务颜色只作为行首色条，不把整行染色。

## 实现

- 纯函数：`frontend/src/helpers/kanbanHierarchy.ts`（显示上级、列内分组、进度、路径、聚焦范围），与列表视图共用 `chooseDisplayParents`。
- 状态：`useKanbanDisplayPreferences`（显示方式与折叠）、`components/project/views/kanban/useKanbanGrouping.ts`（聚焦与分组计算）。
- 组件：`components/project/views/kanban/` 下的列、节点、行、上级参考标题、聚焦栏和切换按钮。分组视图复用原列的滚动容器、分页和「添加任务」。
- 数据：只读 `useKanban` 的看板缓存。任务修改、阿罗娜回执刷新和加载更多都通过原有缓存更新，分组随之重新计算；嵌套关系副本由原有缓存逻辑同步，所以完成子任务会立即反映在上级进度上。

## 已知限制

- 上级卡片未加载时只能显示「进度未知」，需要加载它所在的页或放宽筛选。
- 多层累计进度（例如总目标下全部步骤的完成数）需要每一层卡片都已加载，目前不提供；若需要，可由后端提供按任务的后代计数接口。
- 分组视图不支持拖动排序。

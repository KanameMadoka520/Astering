# 外部 MCP 与聊天插图（aster.44）

阿罗娜可以连接外部 MCP 服务。原有 `/user/settings/mcp` 仍用于让其他客户端操作 Astering；新增的外部连接管理位于 **阿罗娜设置 → MCP 外部工具**，两者方向不同。

## 按需接入

1. 在设置中添加连接，填写名称、HTTPS MCP 端点、实际传输方式及独立 Bearer 密钥。每张卡片独立保存；修改另一张卡片的草稿不会随之提交。
2. 保存并启用这条连接。测试按钮只握手并读取工具目录，不执行订阅、付款或任务等业务工具。更换地址或传输方式需要重新填写密钥。
3. 在对话输入区的 MCP 入口中选择本轮需要的连接。**没有选择表示不连接任何外站**。新会话与场景模板不会自动开启此前的外部连接；继续旧会话可以恢复该会话自己的选择。
4. 阿罗娜需要外部能力时，先通过 `find_tools` 获取外部发现/调用入口，再通过 `find_mcp_tools` 搜索指定连接上的少量工具，最后通过 `call_mcp_tool` 调用准确的服务、工具和参数。

仅列出本轮连接不发起远端请求；指定连接的工具发现才启动握手。未选中的服务不初始化、不拉取目录，其完整工具定义不进入常驻模型前缀。一次发现至多五个完整定义，发现结果总预算 96 KiB；超过预算减少本次返回数量，不截断 Schema。运行器最多保留 32 个发现凭证，每个新的用户轮次与压缩后重新按需发现。常驻模型入口保持稳定，避免切换 MCP 连接破坏前缀缓存。

当前支持 **Streamable HTTP** 和旧版 **HTTP+SSE**，认证为预先配置的 Bearer 密钥。不支持任意本地进程/stdio、自动 OAuth 授权、远端 roots、sampling、elicitation 或需要交互续接的多轮 MCP 请求。普通模型接入与 MCP 凭据各自管理，不共用密钥。

## 本机 Wallos 模板

模板地址为 `https://wallos.tcymc.space/api/agent/mcp.php`，使用 Streamable HTTP。密钥在 [Wallos 的 Agent 接入页面](https://wallos.tcymc.space/agent.php)创建，固定绑定创建它的 Wallos 账号。它与 Astering 登录、模型 API Key、GitHub Token 分开。

本机 Wallos 是无状态 JSON 响应：初始化通知可返回空 202，不提供独立 GET SSE 流。请求使用明确的 `astering-mcp/1.0` User-Agent，无浏览器 Cookie。使用已有公网 HTTPS 域名即可，不为此放开任意私网访问或修改容器网络。

内置策略只信任已核实的本站地址和工具名称：账号上下文、订阅列表/详情、付款列表、基础数据列表、预算读取、审计读取属于只读。修改、新建、恢复属于写入；订阅回收、付款/基础数据删除和整组优惠规则替换属于破坏性操作。其他 Wallos 部署或通用服务，需由用户明确填写信任为只读的工具名；服务商自己的 `readOnlyHint` 仅是描述，不会自动打开权限。

修改 Wallos 数据前先取得真实对象 ID 与 `expected_version`。正式写入使用唯一 `request_id`；显式重试必须保持相同密钥、工具、编号和完整参数。更换密钥后不能借用旧密钥的防重结果。`dry_run` 只是预演，正式执行需新编号。版本冲突先重新读取，不直接覆盖。

Wallos 的完整合同由其仓库维护：[Wallos-tcymc Agent API 说明](https://github.com/KanameMadoka520/Wallos-Remastered/blob/main/docs/agent-api.md)。此功能操作 Wallos 内的记录，不会实际向银行扣款或替用户登录服务商取消订阅。

## 权限与恢复

允许执行需同时满足：连接属于当前账户、连接已启用、本轮明确选中、远端密钥自身授权、本地工具策略，以及当前对话的只读/写入模式。设置中的写入/破坏性操作开关是额外限制。Astering 的“允许删除任务”只控制本地任务；外部操作由自己的连接策略与逐次审核控制。

所有外部写入逐次展示真实来源及准确参数供审核，`auto` 方案也不能跳过。只允许修改指定 Astering 项目时，外部写入被拒绝，避免把本地项目范围误用为外站授权。只读子代理可以按需使用父任务已经选中的连接，仍由后端禁止外部写入。

审核与发现凭证绑定连接配置、工具定义及规范化参数。关闭/删除连接或更改密钥/地址/策略会撤销旧授权并取消相关活动连接；已被远端接收的写入不能据此假定回滚。执行前重新检查，不能把旧审核转移到新地址或新密钥。模型侧使用固定包装入口，远端的 `get_task` 等名称不能冒充 Astering 内置工具，也不会将远端回执贴入本地任务缓存。

意图先持久保存，再调用外部工具；成功、业务失败与结果未知分别记录。HTTP 200 和 JSON-RPC 正常响应中仍可能包含 `isError`，实际错误内容保留。网络中断、重启或写入后无法处理结果时，不自动重放可能已经提交的操作。完整审计留在会话，模型侧大结果提供有限预览与 `read_tool_result` 分页。结构化结果优先于等价文本，避免重复输入；非文本 MCP 内容仅显示其类型信息，不将 Base64 图片或音频当文字塞入上下文。

出站请求使用现有 SSRF 安全客户端，禁止自动重定向，每次请求检查密钥所属 origin，特别防止旧 SSE 的 endpoint 事件将 Bearer 发给另一网站。生产连接使用 HTTPS。JSON 响应、SSE 单事件、完整目录、工具参数和发现数量分别受限；不自动获取远端 Schema 引用。官方 SDK 对任意 JSON 数字使用浮点解码，因此超过 JavaScript 安全整数范围的远端数字 ID 或 Schema 整数会明确拒绝，防止静默改错编号；外部服务与模型工具参数应将这类编号作为字符串使用，避免不同服务商流式协议的数字解码差异。会话绑定后台执行生命周期，结束、审核等待、取消后关闭，不常驻后台轮询。

MCP 设置使用独立账户密文与认证附加数据，GET/保存响应不返回密钥，调试输出不回显凭据。浏览器敏感 mutation 结算后立即释放密钥对象；服务器账户删除清理继承原有生命周期。设置版本防止另一个标签页静默覆盖。

## 聊天图片精确放入任务描述

针对会话里“把附图放到某条记录的具体位置”的需求，提供以下按需发现工具：

| 工具 | 作用 |
|---|---|
| `list_chat_attachments` | 分页列出当前运行可见、已经发送到当前会话的附件 ID、名称、类型、大小和可用状态 |
| `get_task_description_layout` | 读取描述版本、顶层块位置、现有图片索引及指纹 |
| `insert_chat_image` | 把当前会话里可见的图片放在开头、末尾或指定块前后 |
| `update_task_description_image` | 修改替代文字/标题、替换图片，或移动到指定位置 |
| `remove_task_description_image` | 只移除指定展示节点，保留原文件与附件 |

本轮新图片的像素与可调用附件 ID 一起发送给模型。历史压缩只保留引用，需要时通过 `find_tools` 发现 `list_chat_attachments`；清单默认每页 20 项、最多 50 项，本轮附件排在前面，相同 ID 去重。入口由服务器绑定当前账户和会话，不接受模型指定账户、会话或 URL；只列已经发送且本次运行可见的附件，不列未发送草稿、其他会话或本轮之后的新附件。清单不读取文件正文，不返回 Base64、Drive 存储编号或临时下载凭证；文件名只是非可信数据。复看像素仍使用 `view_attachment`，读取与插入各自重新检查文件可用性及权限。

这里操作的是**任务详情描述**，与最初会话实际指向的对象一致，不是项目总览描述或公告。插入前必须读取最新布局；移动、替换、删除同时核对描述版本、图片索引和图片哈希，避免凭字符串猜测位置或覆盖其他人的编辑。定位到顶层内容块前后，目前不支持在段落内部按任意字符位置插图。

图片源只能来自本轮运行器确认可见的聊天附件。模型不能自行传入其他用户、其他会话或任意图片 URL。写入复用既有 Drive 文件和任务附件，不重复写实体字节；共享任务后沿用任务的现有访问权限。三种写入都进入审核。删除展示不删除聊天原图、网盘文件、任务附件或封面。旧版只有加密副本、没有 Drive 引用的图片需要重新上传后复用，系统会明确提示。

写入按统一锁序，锁定任务后重新检查项目范围、账户权限、描述版本与图片指纹；事务失败不留下新附件。成功回执读取受影响任务详情并局部更新编辑器、列表和看板，不整页刷新，也不让缺少附件展开字段的基础回执清空附件列表。

## 验证方法与协议依据

本地 Mage 回归覆盖真实官方 Go SDK 的两种 HTTP 传输、连接隔离、加密、权限撤销、审核恢复、工具定义变化、请求限额、凭据目的地和结果未知；Wallos 互通使用独立临时容器与空数据库，不写生产订阅。浏览器验收使用隔离 API/SQLite，覆盖独立保存、跨标签冲突、对话 opt-in、移动布局和外部审核来源。具体运行日志保存在源码之外，Release 说明列明实际结果。

# 浏览器缓存与私人图片

缓存按资源是否会变化、是否需要权限分别处理。HTTP 缓存交给浏览器管理；应用不在 IndexedDB 或 Service Worker 的运行时缓存里另存整份网盘、对话或附件。

| 内容 | 策略 | 刷新后的行为 |
| --- | --- | --- |
| 内容哈希命名的构建 JS、CSS、字体、图片及版本化 Workbox 文件 | `public, max-age=31536000, immutable` | 同一地址的内容不变，可长期复用；发布后引用新的内容地址 |
| HTML、Service Worker、manifest、固定地址品牌图标及图片 | `no-cache`，配合 ETag | 使用前检查是否更新；未改变时返回 304，不重传正文 |
| 有权限的任务图片、网盘图片及预览、聊天图片、头像、星图图片、项目背景 | `private, no-cache`，配合验证器及鉴权 Vary | 每次重新验证当前权限；内容未改变时复用浏览器里的图片字节 |
| 会话和项目 JSON、密钥配置、实时事件、导出及非图片私人下载 | `no-store` | 不从持久缓存复用业务状态或敏感下载 |

`no-cache` 允许保存，但使用前必须重新验证；`no-store` 才是禁止保存。私人图片的 304 在身份、资源归属及当前访问权限检查之后产生，不能凭 ETag 绕过授权。权限已撤销、引用已移除或文件不可用时，应返回相应错误，不能离线退回旧私人图片。

公网代理可能改变 HTML。本站 Cloudflare 的 JavaScript Detection 会注入安全检测脚本，并移除入口 HTML 的 ETag；该入口继续返回 `no-cache`，每次从网络获取最新 HTML。源站和 1Panel 直连的入口仍支持 ETag 与 304。公网验收分别确认这一安全变换与静态资源、私人图片的实际缓存命中，不为入口的少量传输关闭安全检测，也不把公网 HTML 的 200 宣称为 304。

入口 HTML 和 API 的 Service Worker 网络策略先于静态资源匹配，并遵循服务器的 HTTP 缓存头。不按任意 URL 扩展名缓存内容，防止外部图片及看似静态的接口进入运行时 Cache API。应用激活时只清理本应用、本作用域拥有的旧缓存，不清空整个源中其他应用的数据。

从 .49 起，构建清单仅作为精确的静态 URL 白名单。Service Worker 安装时不批量预下载所有页面；只在浏览器真正访问清单内、同源且属于本作用域 `assets/` 的哈希命名文件时，按需缓存服务器明确返回 `public, immutable` 的真实静态响应。拒绝重定向、HTML 回退、类型不符、Authorization、Range 和私人缓存头；固定品牌图标仍由 HTTP 重新验证。缓存以作用域及发布版本命名，激活时清理本应用旧版本及旧 Workbox 缓存。不预下载私人图片和网盘文件，也不提供离线业务 JSON。

浏览器的 HTTP 磁盘缓存和页面里的 Blob、解码图片内存属于不同层，HTTP 缓存年限不代表资源必须在内存或磁盘里保留一年，不能把它当成内存容量上限。全站查询只在当前认证身份的内存中复用；请求被拒绝或身份变化时，继续遵守权限检查与清理机制。

原策略曾给固定品牌图片一年以上的 immutable，因此本次把现用图标及登录头像的引用更新为 `?v=x40`，绕开已经保存的旧缓存规则。后续同一固定地址遵循条件重验证，无需靠用户反复清空整个浏览器缓存才能更新。

304 主要节省网络传输。某些图片接口仍需读取、检查或解密文件后才能确认响应，不把它描述为完全省掉数据库、磁盘或图片处理开销。预览验证器包含原文件、尺寸和生成版本；更改预览编码规则时需要相应更新生成版本。

依据：[MDN HTTP 缓存指南](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Caching)、[RFC 9111](https://www.rfc-editor.org/rfc/rfc9111.html)。

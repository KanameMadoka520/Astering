# 阿罗娜工具模块范围

工具模块用于限制一轮执行可以访问的业务板块。它与模型连接、账户权限、项目写入范围、审核策略及外部 MCP 连接共同生效，不会授予用户原本没有的权限。

## 使用方式

输入框旁的「工具」提供每个板块的三档设置：

| 模块 | 关闭 | 只读 | 读写 |
| --- | --- | --- | --- |
| 项目与任务 | 隐藏并拒绝项目、任务、日历、看板、打卡等业务工具 | 可以查询，不能写入 | 按账户权限、项目写入范围及审核策略操作 |
| 星图 | 不发现、不调用星图工具；新旧会话均默认关闭 | 查询允许访问的空间、记录、主题及历史版本 | 创建和修改允许访问的内容；每次写入均须审核 |

「场景与偏好」可保存个人模板及默认选择。外部 MCP 仍在其独立选择器中启用连接；模块切换不会替用户选择 MCP 连接。全局只读对所有工具有效。把本地模块从只读升为读写时，其他本地模块保持原有实际权限；若当前还选择了 MCP 连接，界面会先明确说明全局写入上限的变化，并要求确认。关闭本地模块不会顺带修改 MCP 的全局上限，外部写入仍逐次审核。

执行中、等待审核及编辑已有消息期间，执行配置入口锁定。已开始的运行、继续执行、审核和失败重试沿用这轮的配置快照；需要修改范围时先停止，再发送新请求。切换后生效的配置会出现在下一轮执行记录与提示词预览中。关闭模块限制新的访问及额外历史工具结果读取，不会删除已存在的对话、摘要或模型已经见过的内容；彻底隔离上下文时应新建会话。

## 协议与服务端边界

`RunInput`、场景 `AssistantOptions` 和已保存的运行配置使用同一字段：

```json
{
  "mode": "write",
  "tool_modules": {
    "project_tasks": "off",
    "compass": "read"
  }
}
```

每项为 `off`、`read` 或 `write`。旧配置未传字段时，项目任务兼容为 `write` 选择值、星图为 `off`；`mode=read` 把所有 `write` 的实际能力降为只读，选择值本身仍会保存。无效枚举拒绝保存，内部归一化也会关闭无效值。

`ScopedTools` 与 `ValidateTool` 共用分类规则；工具发现、`invoke_tool`、已加载的旧定义、审核后的执行、运行恢复和只读子代理均再次检查。子代理继承模块范围并保持只读。历史 `read_tool_result` 按原操作来源检查，包括引用链、旧版发现目录及子代理回执；无法证明来源或循环引用时拒绝额外读取。

工具定义继续按 `find_tools` 延迟加载。项目任务关闭时，常驻的三个项目任务读取入口以及相关系统提示词说明同时移除；星图工具不常驻灌入每轮请求。诊断端点 `GET /api/v2/ai/prompt` 接收 `project_tasks`、`compass` 查询参数，预览当前范围对应的目录，响应仍为 `no-store`。实际模型请求只加载本轮需要的定义，不应把诊断用的完整允许目录误认为常驻输入。

这个设计参考了 [Codex MCP 的启用与工具白名单](https://developers.openai.com/codex/mcp)及 [OpenAI 延迟发现工具的设计](https://developers.openai.com/api/docs/guides/tools-tool-search)，在现有服务商无关的发现与调用协议上实现；不要求模型服务支持专有工具搜索接口。

## 星图工具

读取工具：`list_compass_spaces`、`get_compass_space`、`list_compass_entries`、`get_compass_entry`、`list_compass_revisions`、`get_compass_revision`、`list_compass_topics`。

写入工具：`create_compass_space`、`update_compass_space`、`create_compass_entry`、`update_compass_entry`、`restore_compass_revision`。记录状态可以归档、移入回收站或恢复为活动状态；不提供永久删除、改变共享归属或绕过文件访问的工具。

列表分页并使用摘要，正文按需读取。更新须提交刚读取的 `revision`；恢复历史同时须提供所选历史 `revision` 与当前 `expected_revision`。服务器合并省略字段时不偷换调用方版本，审核后也重新确认当前身份、空间权限和版本。恢复正文生成新版本，保留当前置顶及归档／回收站状态。

成功回执经查询层按空间及记录定向刷新；先取消可能迟到的旧读取，不刷新无关任务，不把模型结果直接赋给编辑器。后台更新不会覆盖未保存草稿，旧草稿提交仍须通过原版本冲突检查。

增加模块或工具时，须同时补目录分类、执行校验、历史结果来源、恢复、审核、子代理、中文和英文名称、审核摘要及成功回执更新的回归。不能仅隐藏开关或只过滤首次发现。

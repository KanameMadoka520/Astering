# 阿罗娜手机对话布局

手机浏览器的对话页面以正文和输入为主，避免全站顶栏、会话栏与多排配置同时占用高度。布局参考本次提供的手机截图，复用现有会话、语音、附件和配置组件，不新增平行聊天状态。

## 页面与输入

- 手机 `/ai` 只保留一行会话顶栏：历史、当前标题、新建和更多操作。点标题查看会话详情。全站搜索、通知、账户、计时和导航可由历史抽屉底部“打开 Astering 导航”进入，仍使用原组件实例。
- 输入区保留文本、附件、语音、模型／工作方式摘要和发送；执行中仍提供停止与插话。完整模型、场景模板、联网搜索、工具能力、MCP、权限及运行设置按需打开配置面板。
- 模型摘要必须显示当前真实配置，长名称省略时保留完整可访问名称。运行中的权限范围继续锁定，收拢界面不能放宽执行权限。
- 配置面板关闭、键盘弹出、横竖屏切换和浮窗最小化不得重建输入框或丢失草稿、附件与流式状态。手机面板适配可见视口和安全区；桌面继续保留站点顶栏和宽屏布局。

## 信息层次

回复默认保留模型、GMT+8 时间、实际耗时、已报告的输出速度、复制和分支操作。轮数、Token、缓存与请求诊断收在“运行详情”；会话硬盘占用、附件数和压缩摘要收在“会话详情”。展开后仍可完整查看，不能删除实际记录。

运行阶段、审核、错误、重试与终止必须直接可见；工具调用和中间输出沿用既有显示偏好，不能因一次新工具调用吞掉前面的过程。Token 和速度只能使用服务商与真实请求报告的数据，不为视觉效果估算实时 Token 进度。

## 后续验收

变更这些布局时检查 320px、390px 和 430px 手机、中英文、长标题／模型名、空会话、已完成与执行中会话、浅色与深色、桌面和浮窗。必须实测键盘仅改变 `visualViewport` 的场景，并确认账户／搜索／通知在站点抽屉内可以实际操作。

通过 `mage test:e2e` 使用隔离数据库和合成会话验收，不使用真实模型或生产登录。测量正文与输入区高度，并检查截图与交互；不能仅以元素存在或某一张静态截图判定可用性。

## 草稿、已读与图片恢复

直接打开另一会话链接或使用浏览器前进／后退时，恢复该会话自己的未发送草稿；只有上传或发送首次建立会话时，才迁移当前输入。不能把旧会话的文字写进目标会话。

已读依赖回复末尾真实可见：配置、偏好、网盘、导出、历史管理及图片预览覆盖正文时，保留未读；关闭后重新等待可见时间。图片请求失败提供原位重试；下载成功复用同一个 Blob 恢复预览，不额外下载一份。重试按钮消失时，仅在用户仍把焦点留在该按钮上才将焦点移到图片预览，不抢走用户后来移动的焦点。

# 项目时间线与进度口径

年度页面 `/projects/history` 默认展示项目时间线。它把有明确计划日期的任务汇总到所属项目，用来查看一年中的安排覆盖、空档、截止日期和当前进度。完成/归档事件仍由原有生命周期接口提供，属于另一种记录。

## 什么会进入时间图

每个任务的日期区间和截止日期分别判断：

- **时间段**：有开始时间，以及结束时间或截止日期（结束时间优先）。区间计入排期覆盖、已过日期和项目的时间条。
- **截止节点**：有效的 `due_date` 在所选年份内显示为菱形节点（全部完成为空心、仍有未完成且已过期为红色、其余为实心），不形成时间条，也不增加排期天数或已过天数。只有截止日期的任务、以及区间落在其他年份但截止日期在本年的任务，计为“只有截止日期”（`deadline_only_tasks`）；它们照常计入任务数、进度和逾期数。本年只有截止节点的项目在行内注明“只有截止日期，未设置开始–结束区间”。
- **无效区间**：结束早于开始或日期超出 1970–9998 年的区间不绘制，计入 `invalid_tasks`；若同一任务的截止日期有效，截止节点仍会显示，所以这个数字是区间警告，可能与有日期任务重叠。
- **不进入图表**：完全没有日期的任务（`undated_tasks`），以及只有开始或只有结束、又没有截止日期的任务（`incomplete_tasks`）。页面分两行说明数量和需要补充的日期；`excluded_tasks` 等于两者之和。

日历格的颜色只按有时间段的项目数计算；只有截止日期的日子不着色，只显示截止圆点，提示文字给出当天截止数量和涉及的项目数。选择某天时，当天有时间段或有截止节点的项目都会列出。年度统计显示有日期的项目、排期天数（只按开始–结束区间计）、已过日期、有日期任务的完成数、只有截止日期的任务数和逾期任务数。

不使用项目或任务的创建时间、更新时间来猜测工作开始日期。缺失日期的任务无法分配到某一年，因此“缺失日期”和“无效区间”数量针对当前可访问的筛选范围整体统计，不是假称当年漏掉的数量。

每个项目只汇总它的直接任务，不把子项目再重复算入父项目。已归档项目同样可以查看；所有统计、排除数量和年份边界都先检查当前账户的直接、继承、团队或链接共享权限。

## 时间与进度分别表达什么

- **计划覆盖**：各任务明确日期区间的并集。同一天同一项目只算一次，不填满不连续阶段之间的空档。
- **已过日期**：计划覆盖中截至今天的部分；任务已完成且有实际完成时间时，进一步截止到该完成日期。未来日期不算已过日期。
- **当前进度**：当年有日期覆盖的任务完成比例的算术平均值。已完成任务按 100% 计算，其余采用任务设置的完成百分比；不按时长加权。
- **截止日期**：仅采用明确的 `due_date`；结束时间不会自动冒充截止日期。分别给出最近将到期日期、最早逾期日期和最晚截止日期。

计划覆盖不证明每天实际投入了工时，已过日期也不等于完成进度。当前进度不是历史每日进度快照；修改任务日期或进度会更新这张汇总图。需要工时证据时使用工时记录；需要查看完成/归档操作时使用生命周期记录。

## API 与阿罗娜

`GET /api/v2/projects/timeline` 接收 `year`、`timezone`、`project`、`status`、`q`、`day` 和 `page`。日历统计始终覆盖所选年份；选择某天只筛选项目明细，不改变年度统计。项目明细每页 24 项，按明确开始日期和项目 ID 稳定排序。

日期按照传入的 IANA 时区转换后处理，支持跨年、闰年与夏令时。跨度裁剪到所选年份，并将相邻或重叠日期合并为连续区间；图表数据的上限由年度天数决定，不向前端返回全部任务描述。

阿罗娜通过按需发现的 `list_project_timeline` 查询同一套统计。模型收到项目摘要、当前进度、截止日期和分页信息，不接收渲染用的逐日地图及区间数组，以减少工具返回内容。`list_project_history` 继续表示完成、重开、归档、取消归档等实际操作记录，两者不混用。

这是只读聚合，不增加迁移，不改写任务，不自动完成或归档项目。

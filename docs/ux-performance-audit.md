# 全站体验与性能审查（v2.7.1-tcymc.35）

本文记录 .35 这一轮「个人记录 + 以后邀请协作者」的体验、文案与性能审查：查了什么、发现了什么、改了什么、为什么没改其余的。基线为 `cac6020cf`（.34）。设计约束沿用 [whole-site-design.md](whole-site-design.md)，查询与缓存规则见 [.agents/docs/api.md](../.agents/docs/api.md)。

## 一句话结论

上一版最容易误导人的地方不是外观，而是「不知道」被说成了「没有」：共享名单加载失败时显示「尚未共享」，子项目明明通过上级被团队访问却显示未共享，退出登录或会话过期会清掉页面承诺保留的草稿，Esc「放弃」后过几秒又把放弃的文字保存掉。本版先修这些说错事实或丢数据的问题，再处理确认框、加载/错误/空状态、键盘与触屏，以及阿罗娜流式输出时的主线程开销。

## 范围与方法

审查覆盖：工作台与近期、项目列表与视图（列表/表格/甘特/看板只做回归检查）、任务详情、团队与共享（用户/团队/链接）、公开页、星图私人写作、网盘、项目回顾、阿罗娜（全页、悬浮窗、设置）、账户设置、全局导航与移动端、通用组件（Modal、CreateEdit、下拉、分页、提示、快捷操作、快捷键）。

- **三名专项子代理**（Claude Code 自定义子代理，模型 `claude-opus-5-5`），先只读审查各自领域，再在互不重叠的文件集合内实现：
  - collaboration-designer：共享、团队、链接分享、公开页、项目设置、访问标识。
  - personal-workspace-designer：工作台、星图、网盘、回顾、设置、外壳与通用组件、任务详情、项目视图。
  - performance-engineer：阿罗娜流式渲染与悬浮窗、对话框观察器、全局计时器与轮询、图片按需加载、阿罗娜设置。
- **独立的用户旅程审查**：8 条端到端旅程逐行追踪代码，每条旅程再由一名对抗性复核者尝试推翻每条发现。共 101 条：99 条确认、2 条驳回；复核后严重度为 P0×1、P1×6、P2×43、P3×49（复核者普遍下调了严重度）。
- **根代理与独立复核者**审查后端与数据正确性，录制 .34 生产构建的 CPU 画像，实现流式事件的增量协议，并在独立工作树复核草稿与共享修复。40 个文件的复核增量已合并进最终源码，账户删除后端也已提交；定向验证与全局检查分别记录，不将已合并等同于全局验收完成。本文区分组件合成测量、SSE 合成测量和真实应用浏览器采样；最终构建的浏览器对照仍待填写。
- **证据标准**：每条发现给出 `文件:行`；关键回归测试已在未修复代码上运行并确认失败（逐项记录在各子代理的进度报告中），少数测试是修复前后都应通过的兼容性守护，报告中单独标出；性能结论来自可复现的合成夹具，估算明确标为估算。

严重度：P0 = 说错隐私/访问/保存状态或丢数据；P1 = 阻碍或误导常见操作；P2 = 摩擦与不清晰；P3 = 打磨。

## 设计决定

- **D1 不知道不等于没有。** 告诉用户「谁能看到我的数据」的列表，只有在服务器确认为空时才能说「没有」。首次加载显示骨架；失败显示可重试的错误（`role="alert"`），不渲染空状态句子；后台刷新保留已有内容；刷新失败时保留旧行并注明可能过期，不给出权威结论。
- **D2 默认私有，共享必须明确。** 只用现有 API 字段标注和解释，不改权限，不自动共享或发布。
- **D3 确认框可预期。** 删除、移除、撤销等确认框在请求进行中保持忙碌（Esc、遮罩、取消与关闭无效，不能重复提交），只在成功或主动取消时关闭；失败时保持打开并写明对象，用户可以重试或取消。`Modal.vue` 现在对返回 Promise 的 `@submit` 自动做到这一点，并提供 `confirmLabel` 写明具体操作。
- **D4 改变访问范围的默认值保持关闭。** 复制项目默认不复制共享（其中包括会生成新公开链接的链接共享），开启时说明谁会获得访问；新建或移动到上级项目时说明会继承上级的访问；删除团队前说明其星图空间会被永久删除。
- **D5 用「实际访问」的语言，不说「私有」。** 后端规则：所有者与任一上级上的用户/团队授权都作用于全部子项目，任一上级的管理员权限保留；共享接口只列直接授权；链接共享不继承；站点管理员可能读取所有项目。所以界面可以说「与你共享」「通过上级“X”共享」「没有直接或通过上级共享给其他人」，但从不说「私有」「仅你可见」；看不到的上级如实说明。网盘的管理只属于本人，但附加到共享项目任务上的文件对该项目成员可见，文案照此表述。
- **D6 草稿按账户与服务器保留（根代理决定，复核修正已合并）。** 会话过期或被撤销不能悄悄抹掉未保存的写作。任务描述、新评论、已有评论的编辑与星图草稿以「API 地址 + 身份」划分；退出登录仍清除令牌、设置、历史与查询缓存，只保留明确划分了范围的草稿；主动退出时询问是否一并删除本机草稿（默认保留，取消即不退出）。描述草稿区分「没有草稿」与「有意清空正文」，保存请求尚未得到服务器确认时继续保留本机副本。草稿写入者捕获作用域与代次凭据（lease），清除后重新登录也不会使旧回调重新获得写入或清除新草稿的资格；网络保存及其回调同样绑定发起时的账户、服务器与对象。草稿只在同一账户、同一服务器重新登录后恢复。本机草稿是未加密的明文，文案不称其加密或已存到服务器。

账户删除清理已提交为 `3eef085b0`，范围是 `models`、`tcyai`、`bark`、`tcyshowcase` 的 25 个 Go 文件；没有新增迁移、API、公开 schema 或依赖。这里指账户实际删除，申请删除或事务回滚不会提前撤销任务、删除文件或设置删除标记。

- **私有内容与请求：**删除用户行的事务成功后，通过 `OnCommit` 清理阿罗娜模型密钥、设置、偏好、会话、旧附件目录和所属缓存；清理 Bark 设备密钥、设置与发送队列；移除该账户的公开展示页草稿和已发布内容。同进程取消正在运行及压缩的阿罗娜任务、Bark 测试和投递请求，并拒绝迟到的保存、结算和 checkpoint。
- **跨进程与失败恢复：**用户行缺失是持久的删除事实，残留的账户目录、设置文件、Drive 行和展示页 owner key 支持启动时及小时定时重试。私有文件写入持用户行写门到本地落盘完成；从另一进程删除账户后，只有活跃请求按约 2 秒间隔检查用户是否仍存在，查询设有 2 秒期限，并在模型轮次边界复核。数据库错误会使请求停止继续运行，但不会把仍存在的账户永久标成已删。取消是本机取消，不能撤销外部服务已经接受的请求。
- **共享文件：**任何私有模块清理失败时，先保留 Drive 的附件引用保护。回收逐文件加锁并重新检查任务附件、项目背景、头像或导出、星图挂载与当前/历史图片及空间背景、其他会话引用；仍被引用的文件保留，所有引用消失后再回收。存储失败保留回收标记供后续重试，不转移文件所有权。
- **公开展示页：**全局 `pages.json` 的保存、撤下、账户清理和重试使用同一固定 OS 文件锁，覆盖完整的读取、修改、原子替换过程；清理一个账户不会用旧全量快照覆盖另一个账户的新内容，也不会被另一进程的旧保存恢复。固定 `.pages.lock` 不删除，进程退出由 OS 释放锁；临时快照只在持锁时回收。

账户删除不会替代浏览器本机草稿管理或服务器备份管理。历史上未带账户 ID 的 `.settings-*`、`.push-*` 临时碎片无法可靠归属，本版不猜测删除；新增临时文件带账户 ID。系统不支持手工复用已删用户 ID。后端具体测试与平台边界见下文。

## 实际任务弹窗与连续导航复核

最终整合又发现：原先 `useRouteWithModal` 手工渲染任务组件，位于 RouterView 的兄弟节点，任务内部的组合式离开与更新保护没有活动 route record。普通路由组件测试通过，不能证明点击看板卡片打开的任务弹窗也受保护。修复先在真实 WebHistory 中复现，再让弹窗使用 RouterView 原生的 record、实例与 guard 生命周期。

任务弹窗打开关联任务时保留原项目背景；从全页任务跳到另一个任务仍使用全页。兼容旧 history state 时，同一 task record 不能同时成为前景与背景，以免两个实例的 guard 互相影响。程序导航的 hash/query 与确认后的任务 URL 重放会保留已验证背景，浏览器后退、前进和显式全页 state 则遵循各自历史记录；更新 state 会保留 Vue Router 的 position、back、forward 和 scroll 信息。

真实 Description + QueryClient + WebHistory 回归覆盖保存失败后留在原任务、保留有意清空的草稿并继续、关联任务背景、关闭及后退。任务页复用到下一任务后，确认离开使用的临时绕过状态会在 finally 中复位，下一次失败编辑仍受保护。最终定向 8 文件、87 用例通过；强制全项目 TypeScript 为 0 诊断。完整 E2E 结果仍见最终验收表。

退出登录的整合复核还验证了缓存清理：有效身份、没有 session，以及解码后缺少身份字段的本机令牌都只清理一次服务端查询缓存。最后一例在原单次清理修正上仍复现 0 次清理，现由 `setSession` 返回实际身份变化情况来决定补清理，保留草稿 lease 与退出时的账户隔离；账号及草稿定向 3 文件、26 用例通过。

## 创建后立即修改的时间精度回归

创建任务时，ORM 返回的对象保留纳秒，而数据库的既有时间列实际保存为整秒；普通更新会回读数据库时间。因此，同一秒内创建后立即更新可能看起来比创建响应更旧，被前端原有的过期响应保护正确拦住。本版在创建事务内完成 Done 桶、指派与提醒写入后，按 100 条一批回读实际保存的 `Created`、`Updated`，同步响应与创建事件中的时间；不改数据库结构、权限、时间列精度或前端过期保护。

新增回归在旧实现上四例均实际失败。修复覆盖单任务、客户端传入 Created 仍由服务器管理、含 Done 桶的批量创建，以及 103 条导入跨查询分批边界；断言响应、数据库、事件时间一致，其他返回内容保留，立即更新不会时间倒退。SQLite 和禁用缓存的隔离 PostgreSQL 相关测试各 5 个顶层、26 个子例通过；为满足复杂度规范提取 helper 后，最终源码在两种数据库重新执行四个新增子例均通过。最后全局 Go lint 为 0 issues。此修复不改变同一秒内不同更新之间的既有排序能力。

## 分离部署的附件正文清理

修正 E2E 的公开前端地址后，完整套件暴露了另一条真实边界：前端和 API 使用不同地址时，后端只信任 `service.publicurl`，把自身 API 返回的绝对附件图片地址当成外链。因此附件、封面虽已删除，正文和评论可能残留引用，旧编辑器保存也无法正确拦住这一引用。

本版增加可选 `service.apiurl`，默认留空；现有同域部署无需改配置。前后端分离时可明确设置可信 API 根，例如 `https://api.example.com/` 或含部署前缀及 `/api/v2/` 的地址。地址必须是没有用户信息、查询或片段的绝对 HTTP(S) 地址；不从任意图片或请求 Host 推断可信来源。

公开前端与 API 地址分别匹配自身的协议、主机、归一化端口和路径边界，不跨用另一个地址的前缀。协议相对图片继承公开文档的协议。其他域名、其他端口、相似前缀、编码斜杠及其他任务的图片继续保留；`data-src` 的优先规则不变。回归检查删除和迟到保存的正文、评论、封面、事务回滚及 Drive 原文件保留。旧实现实际复现 2 个顶层、7 个子例失败；修复后 SQLite 7 个顶层、42 个子例通过，禁用缓存的隔离 PostgreSQL 3 个顶层、8 个事务子例通过，最后全局 Go lint 为 0 issues。配置样例由 Mage 生成并按仓库既有规则保持为忽略产物。真实浏览器复验结果另见验收表。

### SSE 传输与缓存更新合成测量

根代理对同样规模的人工状态（40 步、200 条 2 KiB 工具回执、80 KiB 最终文本、250 次逻辑更新）测试完整快照与 `delta-v1`。客户端实走事件消费者和真实 QueryClient；不包含 Markdown/DOM 渲染、模型响应、网络延迟或真实用户流量。

| 指标 | 完整快照 | delta-v1 |
|---|---:|---:|
| 未压缩 SSE 帧字节（含 JSON 与 event/data 分隔符） | 116,578,340 B | 539,292 B |
| 客户端解析、应用、发表缓存的进程 CPU | 515.146 ms | 68.315 ms |
| 客户端额外保留堆（GC 后） | 1,856,792 B | 549,472 B |
| 服务端编码进程 CPU | 280 ms | 1,490 ms |
| 服务端编码器额外保留堆（GC 后） | 514,240 B | 1,108,752 B |

该样本未压缩帧字节下降约 99.54%，客户端进程 CPU 下降约 86.7%；**服务端 CPU 与保留堆增加**，因为编码器保存可差分的状态并做完整 schema 的通用差分，避免遗漏工具、中间回复、审核、终态及压缩字段。这是客户端及传输开销与服务端成本的取舍，不是服务端 CPU 加速。

250 次逻辑更新的编码基准没有真实等待 30 秒，也没有实际执行第 25 秒的重连。真实连接初次与重连仍需完整快照；同一夹具若加上一次约 493,701 B 的重连快照，推算总量约 1.03 MB、下降约 99.11%，这是夹具推算而非生产 TCP/TLS 流量实测。保留堆是强制 GC 后的增量，不等于 RSS；CPU 受计时精度、JIT、GC 与宿主调度影响。

本轮优化不声称减少模型 token，也不能将这些合成数值推广为全站 INP 或真实流量收益。原生产构建的 21 次已测导航本来就属于同文档 SPA 切换，不能写成这轮才修复「整页刷新」；最终生产构建的导航、移动端与流式协议验收仍待下表填写。

## 浏览器测试调整的依据

测试修正不等同于产品修复，也不能用放宽选择器掩盖异常。此次另用干净的 `.34` 源码及原测试执行九项基线检查：八项复现相同的旧失败（品牌文案与已有公告按钮造成的 Add 定位歧义）；创建团队一项通过，不能列为旧失败。后者是新测试先等待页面描述，暴露了旧页面原有两个“创建团队”入口，现将点击限定到页头。

WebSocket 通知测试原先等 HTTP 返回后才注册消息监听，但服务端会在 HTTP 返回前派发事件。测试改为先注册监听，再发送请求，保留状态码、消息和内容断言，不延长超时。公开访客测试曾进入空白页：E2E 的 PublicURL 错指独立 API 进程，其内嵌首页只是构建占位；Mage 现指向实际前端预览地址，测试打开真实生成的链接并检查域名来源，没有改写链接掩盖错误。

阿罗娜会话搜索测试还暴露一次防抖等待问题：从归档切回普通列表时，旧缓存的一项记录可以提前满足数量断言；后台刷新为两项后，真正的搜索尚未发出，下一条单元素断言立即失败。测试预先等待实际搜索响应，再检查完整结果；查询键仍按页码、搜索词及范围隔离，取消信号和 placeholder 的范围约束继续保留。该失败的最终复验以验收表为准。

页面全局无障碍通知曾生成一个空的 alert，使弹窗内出现两个 alert。现保留 assertive live region 和原子朗读，不给空容器重复 alert 角色；有视觉提示及屏幕阅读器通知的文本断言分别定位，未删除无障碍播报。最后复核还修复库在视觉去重时不发 start 事件导致重复错误不播报、同一 tick 多条消息互相覆盖，以及提示销毁后留有旧播报文本；使用真实通知库的回归与针对性反向验证确认测试能捕获错误清理逻辑。

## 已知限制与后续

- **共享概览的边界**：只能根据当前用户能读取的项目与共享列表推断；看不到的上级、看不到的团队如实说明为「无法确认」，不推断有效权限上限。直接共享给用户的项目（非团队）在对方当前会话中仍需刷新才出现，因为后端不为此发送事件。
- **草稿**：本机草稿为明文；同一设备上的他人若能打开浏览器存储即可读到。主动退出时可选择删除。无法确定归属的旧版（未划分范围）草稿在退出时清除并在对话框中说明。
- **注销账户**：已按上文生命周期实现清理；存储故障需等待重试，共享引用保留的 Drive 文件会延后回收。服务器备份与本机明文草稿仍需分别管理；旧版无账户 ID 临时碎片不做猜测式删除，不支持手工复用已删用户 ID。
- **星图空间无法删除**（compass-10）：需要后端功能，本版未做。
- **冻结时延后**的条目见附录，均附原因。

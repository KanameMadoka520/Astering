# 长时间实时听写与个人笔记

`/notes` 用于会议、研究和个人口述记录。浏览器一边采集麦克风，一边向用户选择的语音服务上传 PCM，识别出的最终分句逐条保存；它不沿用阿罗娜短语音输入“先录完、再识别”的 180 秒流程。两种入口分别维护生命周期，不能为长听写取消短语音原有的隐私保护。

## 使用方式

先创建一篇个人笔记，再打开“原始转录”选择已保存的实时识别连接。点击开始与结束即可，不需要一直按住鼠标；手机也使用同样的点按操作。浏览器授权、连接服务商、实时录音、轮换连接和结束收尾分开显示。

目前实时入口接入已实现的 `dashscope-asr` 与 `qwen-asr-realtime` 协议。连接列表只展示当前用户可用的相应语音连接，并显示模型与实际端点，不回显密钥。文件识别协议、OpenAI 兼容协议或其他已有短语音连接不会仅因模型名称类似就被视为支持实时听写。

笔记有两个独立部分：

| 部分 | 用途 | 保存方式 |
| --- | --- | --- |
| 正文 | 用户编辑、整理后的 Markdown | 编辑后延迟保存，支持手动保存与草稿冲突处理 |
| 原始转录 | 服务商确认的最终识别分句及时间范围 | 分句追加保存，不因正文修改而改写 |

临时字幕在最终结果到来前可以反复修订，不能被显示为已经保存。最终分句须在服务端事务提交后才通知浏览器。原始转录目前不单独编辑或删除分句；需要纠正、删改或重新组织时，把选中的文字加入正文再编辑。原始页每页最多 100 条，默认直接显示最新记录，也可以从头向前分页，不为长录音把全部分句挂载到 DOM。阅读、滚动或选择分句时会暂停跟随并保留当前阅读位置；这只冻结阅读视图，不会暂停正在进行的录音与最终分句保存。点击“最新记录”会清空当前选择并恢复跟随；发现未收到的分句时提供明确的刷新入口，不把缺失结果当作已经显示。

标题最多 250 个 Unicode 字符；正文最多 8 MiB UTF-8；单条最终转录最多 64 KiB UTF-8。大小按编码后的字节计量，不能把中文字符数直接当字节数。搜索检索标题与正文，原始转录不会隐式加入正文搜索。

## 长录音、后台与设备限制

服务商连接有独立时限，当前浏览器约每七分钟正常结束一段并重新连接，保留同一篇笔记和累计录音偏移。每段上游音频最多八分钟；这个保护不是整篇笔记八分钟后停止。轮换过程中仍采集短暂缓冲，等待旧连接提交最后一句后才切换，旧连接的迟到事件不能影响新连接。

默认切换到其他浏览器标签页会结束本次采集并保存已经确认的结果。用户可以在本次录音前明确勾选“允许在后台继续”；它只允许标签页暂时隐藏时继续，不保证手机锁屏、操作系统冻结、浏览器回收页面后仍可录音。`freeze`、`pagehide`、网络离线、音轨中断或音频上下文暂停始终停止采集。离开笔记页面、切换目标笔记、退出或切换身份也必须结束原麦克风会话，不能把旧结果写入新的笔记或账户。

“尽量保持屏幕常亮”同样需要用户明确选择，只在浏览器实际取得 Screen Wake Lock 后显示生效。权限拒绝、浏览器不支持或系统释放时应准确显示未生效，不影响前台听写。迟到的授权须重新核对原录音、当前身份、可见性与选项，释放已经失效的锁，不能让它覆盖下一次录音的状态。后台继续与常亮默认关闭，不暗中扩大短语音录制权限。

长录音无法保证设备锁屏后永不间断。浏览器测试不能代替真实 iPhone、Android、系统省电模式和麦克风权限检查。

## 弱网与恢复

音频只在内存中短暂缓冲，不写 IndexedDB、Local Storage、Service Worker 缓存或服务器音频文件。浏览器主线程队列至多五秒 PCM，AudioWorklet 最多保留三个等待主线程确认的 100 毫秒帧，WebSocket 还有独立的拥塞阈值。溢出时明确暂停，不让主线程或 MessagePort 无限积累音频，也不静默丢弃后继续假装完整录音。

上游完成轮换后，待发音频最多按两倍实时速率平滑追上，避免瞬间上传整段积压。界面显示真实已上传字节、采样速度、经过时间和缓冲秒数，不编造服务器处理百分比。停止后先 flush 最后不足一帧的 PCM，再等待服务商最终结果和提交回执；收尾有界超时，不能一直占着麦克风。

断线、权限变化或保存失败后暂停，由用户确认是否继续。已经提交的最终分句保留，下次读取原始记录即可恢复；临时字幕与未确认音频不能当作已保存。保存失败返回的最终文字允许用户复制补救，但不能谎称这些文字已入库，也不能直接自动发送阿罗娜。正常轮换不是失败重放，未知结果的故障不能通过无条件重发音频制造重复分句。

## 权限、存储与删除

笔记始终属于创建它的个人账户。只有当前活跃真人的登录会话可访问；管理员、超级管理员、机器人、项目成员、公开分享与 API Token 均不能继承笔记内容权限。笔记不默认进入阿罗娜工具目录、MCP 服务或项目共享范围。用户可以选取需要的转录并预览整理要求，再把文字带到阿罗娜输入草稿；这一步不会自动发送模型请求、覆盖已有聊天草稿或开启笔记工具。草稿包含明确的源笔记标识，跨页面交接只在当前标签页内存中保存，URL 只携带一次性标识，不能包含私人转录正文。

如果希望阿罗娜直接查找、读取或保存笔记，打开聊天的「对话配置 → 工具」，将「个人笔记」从默认关闭改为只读或读写；也可保存为个人场景模板。仅整理带入聊天的选中文字无需开启。只读允许分页搜索本人笔记、读取正文和原始转录；读写另允许创建、修改与按单独删除许可删除笔记，所有写入均需逐次审核，并保持编辑版本校验和草稿保护。执行中的配置沿用启动快照，需先停止才能变更下次请求的范围。具体工具与安全契约见[工具模块范围](agent-tool-modules.md#个人笔记工具)。

音频会发送到该账户明确选定的识别服务，密钥沿用服务端保护与出站安全机制。服务端只持久化笔记及文字分句，不保存录音原件；这不代表外部服务商没有自己的数据政策。笔记保存在数据库，不能把“没有音频文件”误解为“没有私人数据需要备份”。

个人空间接口分别报告 `note_count`、`note_content_bytes`、`note_transcript_bytes` 与 `note_text_bytes`。它们是标题、正文和最终分句的逻辑 UTF-8 长度，独立于网盘及聊天文件统计，不加入文件 `total_bytes`，也不声称删除文字会立刻回收等量数据库磁盘块。

删除笔记需要明确确认，随后在一个事务中永久删除正文与全部原始转录，没有网盘回收站。其他笔记、项目、任务、聊天和网盘附件不受影响。删除账户时同时清理其笔记与分句；写入需在原用户凭据锁后重查当前身份与笔记所有权，撤销登录、停用或删除后，迟到的最终结果不得重新建立数据。

## 接口与并发契约

### 反向代理部署

实时听写使用独立的 `/api/v2/notes/live` WebSocket。已有实时通知的 `/api/v2/ws` 放行或代理配置不会自动覆盖这个新地址；如果源站成功而经过域名返回 HTTP 426，应先核对反向代理有没有转发 `Upgrade`／`Connection` 握手头，不能直接归因于 WAF。

Nginx／OpenResty 可在本站已有 `server {}` 内加入[精确路径配置示例](../deploy/nginx-notes-live.conf)，按实际部署调整上游地址。示例保留来源 IP 与转发语义；位于 CDN 后时，仍需沿用[已有的可信来源配置](1panel-waf.md)，不能信任任意客户端提供的转发头。新路径保持 HTTP/1.1、关闭代理缓冲，并给静默阶段留出 600 秒读写超时；浏览器正常情况下会更早轮换上游连接。

修改前保存原文件并记录校验值，执行 `nginx -t` 后温和重载。分别验证直连与公网握手返回 101，以及无效首帧令牌得到认证拒绝；这种探针不会登录账户、写入笔记或调用识别服务，也不能替代真实麦克风与服务商联调。不因新增接口便批量放行整个 API 或关闭 WAF。

### HTTP 与文字写入

所有 HTTP 路径均在 `/api/v2`；私人成功及错误 JSON 保持 `Cache-Control: no-store`。

- `GET /notes`：标准分页，可按 `q` 搜索及 `pinned=true|false` 筛选；置顶优先，然后按更新时间、ID 倒序。列表省略完整 `content`，预览使用 `excerpt`。
- `POST /notes`、`GET /notes/{id}`、`PUT /notes/{id}`、`DELETE /notes/{id}`：创建、完整读取、编辑保存及永久删除。所有者、计数与时间戳由服务器决定。
- `GET /notes/{id}/segments?after_id=...&per_page=100`：按服务端 ID 升序向前读取，返回 `items`、`total`、`has_more`、`next_cursor` 与 `from_end=false`；空页保留原 cursor。
- 同一路径的 `latest=true` 直接读取最新 `per_page` 条（最多 100 条），先按索引 ID 倒序取有限结果，再恢复升序展示；不需要从第一句翻完全部历史。此模式 `from_end=true`、`has_more=false`，`total` 仍是整篇总数，`next_cursor` 是末条 ID；与正数 `after_id` 同时使用返回 422。默认请求保持原有向前分页语义。
- `POST /notes/{id}/segments`：以 note + `client_id` UUID 幂等追加。相同文字、起止毫秒及 `timing_estimated` 返回原记录；相同 UUID 的不同内容返回 `409 note_segment_conflict`。首次响应使用持久化后的时间精度，与重复提交的回执一致。
- `GET /notes/live-connections` 与 WebSocket `/notes/live`：列出本人实时连接并开始本次麦克风会话。WebSocket 在第一帧认证，不把令牌放到 URL；运行槽按账户及笔记隔离，同一篇不能并发采集，当前每账户最多两篇。

正文 `revision` 与转录追加独立。保存正文携带最后读取的 `expected_revision`，旧稿返回 `409 note_revision_conflict`；无变化保存不递增版本。后台转录不会覆盖正文或无端使编辑稿冲突。自动生成的 PATCH 特意关闭，避免框架隐式 GET 新版本后绕过旧稿比较。

时间是累计录音偏移，不是墙上时钟。上游没有精确时间时标记 `timing_estimated=true`，界面和交给阿罗娜的引用用“约”或 `≈` 区分，不能因为转换格式丢失估算属性。

## 验证要求

模型与 HTTP 回归覆盖所属用户成功、未共享用户及管理员拒绝、机器人/API Token/非活跃账户拒绝、正文冲突、转录幂等、重试时间戳、游标分页、独立空间统计和账户删除。新表迁移验证二次执行保留数据、唯一约束及无关表的列和索引。

前端回归使用真实 composable 与真实 AudioWorklet 源码，控制迟到权限、授权刷新、隐藏与冻结、后台选择、常亮授权释放、主线程 ACK、轮换、拥塞和收尾；只模拟浏览器设备、网络和语音服务。真实浏览器验收需覆盖中英文桌面、小屏、键盘、草稿保护、保存后重载和失败恢复。没有实际执行的厂商付费调用、手机锁屏或长时间设备测试不能声明已经通过。

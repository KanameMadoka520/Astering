# 阿罗娜会话未读

会话列表中的“未读”和“工作中”分别表示有尚未查看的回复，以及有后台任务正在执行；两者可以同时出现。后台 GET、SSE、刷新列表、最小化浮窗和切换到别的会话都不能把回复标为已读。

## 已读的确认边界

当前会话处于可见页面、助手窗口实际展开，并且回复底部完全进入对话滚动区域，持续 700 毫秒后，客户端才提交已读确认。滚出、隐藏页面、切换会话或身份会取消等待。请求失败保留未读；重新展示或网络恢复后可再尝试，不做无休止轮询。

服务端生成回复收据，包含轮次和该次终态的摘要。确认绑定收据，而非只有会话 ID 或轮次 ID：同一轮重试产生新回复时，旧确认不得清除它。读取接口不写入已读状态，确认不改变会话的排序时间，也不会停止任务、覆盖执行快照或重写工具结果。

已有旧记录首次读取时以当时最新回复作为兼容基线，避免升级后把全部历史标为未读；随后新产生的回复正常进入未读。新会话和分支有明确的基线。失败、停止或中断产生的可见回复／错误同样可进入未读。

## 权限和缓存

`POST /api/v2/ai/conversations/{id}/read` 只允许该会话所属的活跃真人账户，沿用登录会话验证，不提供给阿罗娜工具、公开分享或其他账户。回复确认必须与当前收据匹配；过期重试收据返回冲突。加密文件写入失败时回滚内存游标。

共享查询层仅对仍对应同一回复收据的详情和列表应用确认，防止迟到确认吞掉新回复。HTTP 与 SSE 合并也不得把同一回复已经确认的状态倒退成未读。账户、API 和认证会话变化后的确认须在实际发送前阻止；正常 JWT 刷新继续有效。

后续修改须保留真实 QueryClient、SDK 发送边界、IntersectionObserver 旧回调、失败重试收据和真实后台完成／查看／重载的回归测试。

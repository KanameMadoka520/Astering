# 阿罗娜视图排序（aster.46）

任务已经可以创建、移动栏目及关联父子关系，但这些操作不等于改变视图内的展示顺序。本版增加按需发现的顺序读取与原子排序工具，继续使用既有 `task_positions`，不新建另一套任务或排序表。

## 工具协议

先用 `list_project_views` 确认真实项目、视图类型及栏目，再用 `list_view_tasks` 分页读取该范围的当前手动顺序、任务 ID、前后边界与 `order_version`。每次只返回薄摘要，不重复加载描述、附件或关联树。

支持普通项目中的列表、表格和手动看板。列表、表格可无筛选或使用通常的 `done = false` / `done = true` 筛选；手动看板须指定真实栏目。保存筛选器、甘特图、搜索和其他复杂视图筛选会明确返回不支持，不会悄悄忽略筛选。列表、表格的 `bucket_id` 为 0，手动看板必须为正数；跨栏目移动沿用原有栏目工具。

API v2 提供同一契约的 `GET /projects/{project}/views/{view}/task-order` 与 `POST /projects/{project}/views/{view}/task-order`。读取固定每页 25 条，含 `previous_task_id`、`next_task_id` 和总页数；结果采用 `private, no-store`。顺序版本覆盖成员、实际位置及相关视图配置，不能用标题或评论的普通变更无故使排序计划失效。

`reorder_view_tasks` 接收按目标顺序排列的 `task_ids`、当前顺序版本及相邻的 `after_task_id` / `before_task_id`。两边锚点在移除本批任务后必须相邻；0 表示范围的开头或结尾。服务器验证范围、版本、任务及锚点，原子计算并保存位置，不让模型猜测浮点数。未选任务保留相对顺序。顺序或成员已经变化时返回冲突，模型应重新读取后再制定操作，不能把旧参数自动重放为成功。

排序只改变指定视图的手动位置，不修改任务日期、完成状态、栏目、描述或父子关系。父子树模式仍遵循原有层级关系；排序成功不等于把子任务变成顶层任务。读取结果不能扩大写权限，项目写入范围、账户权限及操作审核继续由服务端执行。

审核沿用当前策略：智能审核及逐项审核会展示所选任务的旧顺序、新顺序和插入边界；自动执行遵循用户已选择的普通批量操作策略。审核期间顺序变动会使旧计划失效。数据库提交结果不确定时，先重新读取实际顺序，不能把未知结果当成“完全没有写入”直接重放。

## 页面同步

成功回执包含真实项目、视图、栏目、已保存的任务顺序、新版本及全部实际变化的 `changed_positions`。界面仅更新对应视图；看板修复沿用保留已加载分页深度的刷新机制，不退回每栏第一页，不强制刷新整个页面。

手动位置和页面当前排序是两件事。列表、表格可能按截止日期、优先级或编号排序，排序偏好保存在本地和 URL 中；服务器保存位置不能代替用户更改这个偏好。工具回执明确说明“手动顺序已保存”，并提供主动的“按手动顺序查看”入口，不自动改写当前筛选、路由或其他浏览器的设置。

仅有实际操作回执、没有模型步骤的记录仍显示工具行和查看入口；不为它合成不存在的思考、轮次或 token 用量。包含正常模型步骤的记录继续走原有时间线，不重复显示回执。工具参数与完整结果仍遵循详情折叠偏好。

## 后续维护

- 读取顺序保持只读；缺少位置不应因为查询而自动写库修复。
- 排序事务遵循现有视图到任务的锁序；批量分配整体计算，不能循环调用会在中途重新编号的单任务移动接口。
- 正常位置间距足够时，只更新被移动的一批任务；缺少位置、重复位置或间距不足时，才整体修复一次。修复保留隐藏任务和其他栏目内未选任务的相对顺序。
- 回执必须包括重编号引起的所有实际位置变化，否则已加载的旧卡片会保留假顺序。结果身份与请求范围须一致。
- 对分页、延迟快照、跨视图、身份切换及过期版本保留回归；有权与无权、只读与写入、项目范围和审核均需验证。
- 等待视图锁后重新检查实际写权限，避免会话授权缓存或 MySQL 的旧快照继续沿用已撤销的授权。独立授权读取有上下文及短时限，立即关闭；SQLite 已持写锁时复用事务，不能另取连接造成互等。
- 不将完整视图的重复顺序塞进每轮模型上下文，发现定义和读取分页按需进行；完整审计与模型摘要保持各自用途。

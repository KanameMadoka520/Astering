# 阿罗娜会话并发

从 `v2.7.1-aster.52` 起，同一个账号的不同会话可以分别生成、压缩上下文、审核后继续或重试。会话 A 正在压缩时，可以到会话 B 发送请求；B 的停止、失败或完成不会终止 A。模型服务商本身的并发配额与限流仍适用。

## 执行边界

服务端的运行槽按「账号 ID + 会话 ID」索引。模型请求与压缩在后台运行，不把账号级别的运行槽当成整段任务的互斥锁。短时共享状态写入、账户清理与现有业务事务仍保留各自的同步机制；没有移除这些保护来实现并发，也没有改变数据库结构或持久会话格式。

同一个会话仍只允许一个生成或压缩任务。运行期间以新请求 ID 再次启动、手动压缩、继续审核、删除或从该会话创建分支会返回忙碌状态，避免两份历史或上下文同时改写。同一请求 ID 的合法重送仍按原有幂等逻辑返回已有结果。普通执行中的插话继续走原有 steering 路径，在安全步骤接纳；手动压缩中的输入保留为草稿，等待压缩结束。对其他空闲会话创建分支不受影响。

不同会话同时修改同一任务时，仍须通过原有权限、审核、版本与数据库事务检查。会话之间不共用消息历史；本改动不承诺把跨会话的多次操作合并成一个事务，也不会自动重放结果未知的外部写入。

## 页面与后台进度

前端记录一组正在执行或压缩的会话，按查询客户端、API 地址、账号及登录会话隔离。每个没有被当前助手窗口直接观察的后台会话拥有独立事件订阅及查询回退；A 完成时只移除 A 的观察者，B 不会因此断开或重新订阅。共享回执登记仍确保同一次操作只更新相关页面一次。

发送、审核继续和压缩成功的响应会登记对应后台任务，离开页面不依赖原组件仍然挂载。手动压缩的 HTTP 确认与 SSE 共用快照协调，迟到响应不能覆盖较新的完成事件。重命名等元数据响应不会改变后台任务登记。

浏览器 `sessionStorage` 仅保存会话 ID 列表，兼容旧版单个 ID；模型密钥和会话正文不写入这里。刷新会恢复本标签页已知的任务观察。此提示不是服务端任务队列，也不表示新设备自动继承其他设备的所有订阅；打开实际会话仍会读取服务端状态。

## 停止、身份与清理

停止操作只取消指定账号、指定会话的任务。HTTP 请求结束、导航或关闭页面不会取消已接纳的后台执行。服务重启仍按既有逻辑将未完成请求标为中断，不自动重试真实操作。

切换账号、API 或登录会话会销毁旧身份的后台观察者，迟到响应不能写入新身份的缓存。同账号的正常令牌刷新保留观察。账号删除会取消其全部运行槽，等待中的后台结果必须通过账户存活、存储根目录及运行槽身份检查，不能把已删除的文件写回来。

## 回归验证约定

并发回归使用可控模型 HTTP 屏障：保持 A 压缩不返回，让 B 分别生成、压缩、停止及重试，确认 B 的模型请求真正到达上游且 A 仍运行。同时验证同会话互斥、无权限停止、请求取消后的后台存活，以及删除账号后所有任务与观察协程结束。

前端验证使用真实查询生命周期，覆盖两个独立事件流、单个会话撤权、压缩响应与事件竞态、迟到元数据、刷新提示和身份切换。可见发送入口另外通过桌面及小屏浏览器检查。新增后台状态不得恢复账号全局 busy 标志，也不能让一个会话的结束或错误清空其他会话的状态。

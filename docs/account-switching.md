# 本设备多账号与安全边界

账号菜单里的“切换账号”用于同一浏览器或 Android WebView 中已经验证过的真人账号。每个设备最多记住五个账号；添加账号仍须输入该账号密码及其需要的二次验证码。登录页可选择记住账号，公用设备应关闭此选项。同一来源的其他标签页一起切换，不提供不同标签页同时使用不同真人账号的假象；公开分享仍保留原本的单标签页身份。

## 凭据与撤销

生产 HTTPS 使用独立的 `__Host-aster_device_accounts` Cookie（Secure、HttpOnly、Path=/、无 Domain），浏览器禁止兄弟子域通过共享父域植入它，避免设备凭证固定攻击。该 Cookie 只在 `/api/v2/user/account-sessions` 及其子路径用于鉴权；其他接口忽略它。HTTP 开发环境使用另一个 `_dev` 名称和窄路径，不能因代理请求为 HTTP 而降级 HTTPS 公开部署的 Cookie。数据库只保存随机设备凭证的 SHA-256，以及已经建立的 SID 关联，列表只返回用户名、显示名、用户 ID、SID 和最近活动时间；它们不包含邮箱、角色、内容、密码、短 JWT 或可恢复的刷新令牌。

设备凭证最多使用部署配置的长会话有效期。每次切换仍在设备行锁与用户凭据锁后重新校验账号、绑定、SID 及会话有效期，旋转该 SID 的刷新令牌，并返回短 JWT。已撤销、过期、停用、锁定或删除的账号不能通过记住的设备重新登录。替换同一账号会清除它在此设备的旧绑定与旧 SID。移除单个账号撤销它的 SID；全部退出撤销全部设备绑定 SID，不影响其他设备。清理 cron 清除过期设备及孤立关联。

Cookie 授权接口要求 `X-Astering-Account-Intent: manage`，并验证 Origin 或 Referer 的完整来源与部署公开地址一致；二者缺失时只接受浏览器声明的 `Sec-Fetch-Site: same-origin`。`same-site` 不够，CORS 允许也不等于允许账号 Cookie 操作。接口始终 `no-store`，切换等写入接入已有登录限速，列表和记住账号同样限制请求速率。真人登录绑定端点不接受 API Token、机器人或资源受限的助手主体。

## 切换与 Android 兼容

切换前释放旧身份，关闭原生录音会话并卸载私人视图，清除查询和局部观察者；未保存的草稿继续留在原账号的独立命名空间，不能展示给新账号。认证代次隔离旧请求、迟到的录音授权和刷新响应。跨标签页同时监听 token 变更，并在实际取 token 的发送边界同步身份，避免 storage 事件尚未投递的窗口。正常同 SID 的短 JWT 刷新不算切换。

网页切换和刷新共享 `vikunja-token-refresh` Web Lock；原生先 `clearSession` 使旧录音、刷新及 Cookie 回执失效，然后接收新 JWT。刷新响应仍严格只有两条既有 `vikunja_refresh_token` Cookie，分别作用于 v1/v2 的刷新路径。独立设备凭证不出现在 refresh 响应中；原生刷新只提取并发送 legacy refresh 值，浏览器即使发送 Host Cookie，刷新端点也不使用它，旧 APK 的 Cookie 校验无需放宽。不要把设备凭证改成每次刷新都必须更新的新 Cookie。

身份切换不会调用阿罗娜停止接口；后台模型任务继续执行。退出或撤销登录仍遵循现有服务端凭据撤销规则。

## 验证

后端回归覆盖 Cookie 形状、正常刷新后再次切换、跨设备拒绝、移除和全部退出、过期、撤销、停用、删除、同源/CSRF、五账号上限及已鉴权后被撤销的记住请求。前端回归覆盖跨 tab 身份同步、正常刷新、独立公开分享与迟到刷新。真实浏览器验收还须检查手机小屏、键盘、确认、错误恢复及私人内容和录音释放；只检查登录成功不能代替完整账号切换验收。

# tcymc.38 性能与体验验证

本轮直接检查现有实现、采样及回归，不调用 Claude Code，不新增前端依赖。优化围绕确定的重复工作和操作生命周期，保留阿罗娜中间回复、工具结果、审核记录及后台运行能力。

## 已验证的重复工作

`TurnTimeline` 原来把整轮工具结果数组传给每个模型步骤。新增结果会让全部步骤重新做工具参数匹配和分组。现在在父级按轮次分配结果，内容未变化的轮次沿用原数组引用。

固定的组件回归使用 40 个模型步骤、200 条已有结果，向第 40 轮追加一条结果。旧实现会更新 40 个步骤；优化后只更新第 40 轮，前 39 轮没有新增渲染。修改旧结果、删除结果、缺失轮次的历史数据、重复工具 ID、拒绝和重新规划的记录都保留各自语义。这个数字是受控组件的渲染次数，不能直接换算成整站响应速度或 CPU 降幅。

历史附件与网盘卡片虽然已经延迟请求，禁用的查询仍会同步返回缓存 Blob。旧实现会为离屏缓存图片立即创建对象 URL 和图片元素。现在下载和预览初始化都受近视口观察控制，靠近后保持加载状态；手动下载仍可随时进行，缺失、清理和卸载时回收对象 URL。

回归测试分别预置 20 张会话图片和 60 张网盘缩略图：远离视口时创建 0 个对象 URL；让一个卡片进入范围后只创建 1 个，并且没有重新下载缓存图片。测试另验证重复可见通知不重复创建、卸载回收及附件失效后的清理。

## 输入、请求与探针生命周期

- 多选框区分输入法组合事件与普通键盘操作，避免确认候选字时选择成员、项目或创建标签。关闭结果列表及组件卸载会取消防抖搜索、加载反馈和延迟聚焦定时器。
- 项目详情和分页列表将查询取消信号传递给生成客户端，并在读取后续分页前检查取消状态。
- 看板栏目删除确认绑定打开时的项目、视图、栏目及账户/API 上下文；切换看板、跨标签页刷新身份、取消后重开及请求迟到都不会复用失效目标或关闭新的确认窗口，失败则保留窗口以便重试。
- 数据库健康检查使用只读会话，不在池中保留一个无需使用的事务连接。所有探针共享最多两秒的期限，遵循更短的调用者期限或取消；Redis 客户端启用显式上下文期限。状态接口原有缓存与响应结构保留。
- 健康检查回归覆盖仅一个数据库连接、连接池占满、调用者取消和默认探针上界；Redis 回归通过本地测试服务器故意不响应 PING，验证网络读取会按期限结束。

## 浏览器验收方法

生产基线与最终版本采用同一个 Chromium、同一视口和导航顺序，一次热身后各采样三轮：首页、看板、阿罗娜、网盘、星图、项目时间线、团队。保存 CDP 主线程任务、布局、样式、长任务及 JavaScript CPU profile，可在 Chrome DevTools 加载 `navigation.cpuprofile`；火焰图使用本机采样生成。

只读生产验证阻止业务写入；功能交互通过 `mage test:e2e` 在独立测试数据库运行。桌面及窄屏检查页面溢出、运行异常、导航和图片预览，并覆盖明暗主题、中英文、任务创建和修改、看板分组与栏目操作、上传、工具记录及悬浮助手。

这些是本机浏览器的合成采样，不是真实用户 INP。自动化点击、观测器和 CPU profiler 有开销；线上内容及共享服务器负载也可能变化。页面就绪时间、主线程任务耗时和渲染次数分别报告，不把不同指标互相替代，也不从未强制 GC 的堆大小推断内存泄漏。包含私人内容的截图及原始采样保存在服务器私有工作日志，不提交到公开仓库。

# 阿罗娜工具加载与恢复

阿罗娜的模型请求只携带稳定的常驻入口。扩展操作通过 `find_tools` 按需获取完整参数定义，再通过 `invoke_tool` 调用，避免每轮都重复发送整个工具目录。

## 加载状态与权限是两回事

`TOOL_NOT_LOADED` 表示当前执行状态没有对应工具定义。它本身不能证明账户无权限、任务不存在或参数内容有误。服务端仍分别检查当前运行模式、删除开关、项目范围、参数、资源权限及需要的操作审核。

该错误在执行副作用之前返回。模型可以重新发现工具，核对当前定义，再提交新的调用；成功的旧写入不会因此自动重放。调试记录中的失败步骤继续保留，最终完成状态与各步骤状态分别记录。

## 跨轮与升级

历史中的完整发现结果可供后续轮次复用，但其定义必须与当前允许的工具目录一致。版本更新改变参数或说明时，旧定义可能仍可阅读，却不再适合作为当前契约。

每轮新的执行上下文会列出 `stale_tool_definitions`：当前模式仍允许、历史中只有旧定义而没有有效当前定义的工具名称，并提示按需重新发现。它只传名称，不主动注入整套工具定义，不改写历史消息或稳定系统前缀。当前只读模式不允许的写工具也不会被列成可重新加载的能力。

工具发现是协议消息，必须保留完整的结构化定义，不能像普通大业务结果一样截成文字预览。单次发现仍最多返回五个工具；普通的大任务或评论结果继续使用有界预览与 `read_tool_result` 分页。

## 压缩、重试与审核

正常持久化执行状态保存已加载工具。旧版记录没有该状态时，重试必须先重建当前失败轮的工作消息，再恢复其中仍然有效的发现定义，不能只查看上一次模型请求中的常驻入口名单。

压缩会移除旧的工作上下文和扩展定义，后续应按需重新发现。审核和重试继续保留原有的权限、状态冲突检查、已确认操作记录以及不确定写入保护；工具定义的恢复不构成重新执行旧操作的授权。

回归覆盖失效定义提示、有效定义复用、只读与删除权限过滤、大型发现结果的跨轮恢复、普通结果体量边界，以及旧版重试不重放已有写入。测试使用隔离数据和本机模型服务，不调用生产会话或真实模型来修改用户任务。

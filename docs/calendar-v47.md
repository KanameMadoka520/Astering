# 日历交互与全天日程（aster.47）

日历继续使用真实任务、账户权限和共享查询层，不另建一套“日历活动”。本轮补全日期选择、当天安排、空白时段新建和明确的全天日期，使月度总览、逐日阅读和精确排期能够连贯使用。原有接口与时区规则见[日历与日程](calendar-v45.md)；其中“尚无全天标志”是 aster.45 的历史边界，本版由明确字段补齐。

## 选择日期与查看安排

- “列表／时间轴／总览”是直接可点的展示入口，原有月、周、日、议程选择仍保留。时间轴可继续选 3、7、14 天及 25%–250% 行高，文字不随整页缩放。
- 月视图将可见月份与选中日期分开。同月选择日期只更新当天详情，不因每次点击都切换查询窗口；跨月导航才改变月份。月份锚点保存在 URL 的 `date`，单独选择的日期保存在 `selected`。
- 月份可展开为整月，也可折成选中日期所在的一周。议程上方同样可展开选日，日期仍使用账户周起始设置。月格保留方向键、Home/End、PageUp/PageDown 导航。
- 当天详情显示任务、真实时间段占用条和当天新建入口。重叠区间计算占用时间时取并集，避免两项同时发生的安排被重复相加；独立截止标记不虚构持续时间，全天条目不伪装成有具体钟点的时间段。
- 日期格单击选择，双击新建；时间轴空白处可以点击预填时刻，拖动选一段时间后新建。拥挤安排可转到当天详情查看，不要求把所有文字挤进极窄的重叠卡片。
- 手机保留可达的“今天”和“新建安排”，并为右下角悬浮阿罗娜留出位置。按钮、时间轴和日期网格需要在真实 320/390 像素设备视口验证。

农历采用浏览器 `Intl` 的中国历法，仅显示日期，不增加第三方节日、黄历或订阅数据。中文默认开启，可在显示设置关闭，偏好保存在 URL 的 `lunar`；不支持该历法的运行环境应安静省略标签。农历的日期输入按选中的自然日处理，不受设备时区影响。

## 全天与精确时间

任务新增 `all_day`、`all_day_start`、`all_day_end`。全天起止为 `YYYY-MM-DD` 自然日，结束日期不包含当天。例如 11 月 3 日一天保存为 `[11-03, 11-04)`，跨时区查看仍是相同的日期。

创建表单向用户显示“开始日期”和包含当天的“最后一天”，提交时将最后一天加一天得到结束边界。全天与定时是不同语义：开启全天不生成午夜时间戳，`start_date/end_date` 保持空；截止时间独立保存。原有午夜任务也不会自动转换为全天。

定时安排和准确时间提醒均按表单显示的账户时区解析，不依赖设备的本地时区。夏令时跳过的时刻拒绝保存；重复出现的时刻必须明确选择 UTC 偏移量。时间轴继续按服务器的真实 23/24/25 小时日边界布局，不用墙上钟点相减生成高度。

普通重复任务仍只显示已保存的当前日期，不预生成未来活动。全天重复使用完整日、周或月推进自然日，不允许小时级间隔。完成任务后才按既有重复规则顺延，与周期打卡属于不同功能。

## 创建与任务详情

新建表单复用项目权限、任务创建 mutation、提醒和重复组件。只有可写且未归档的项目可选；没有可写项目时给出创建项目入口。日期、定时／全天、项目、重复、提醒与优先级属于同一份草稿、同一次任务创建，不在创建后用多笔无保护请求补字段。

提醒与重复各自折叠。定时安排的相对提醒跟随开始时间；全天没有具体开始／结束时刻，只能选择准确提醒时间，或先设置独立截止时间后使用相对截止提醒。切换类型不静默删除已有提醒，缺少锚点时要求用户修改或移除；尚未点击“添加”的准确提醒输入也纳入草稿保护，并在创建时校验。

创建成功打开原任务详情，保留背景日历及悬浮阿罗娜。任务详情可修改或清除全天／定时日程，清除日程保留任务和独立截止。表单保留原有账户、API、认证会话及实际 SDK 发送边界的身份保护；卸载或身份变化后的迟到结果不能导航或覆盖新草稿。创建失败保留输入，可重试。

转换为全天或清除具体起止时间时，已有的开始／结束相对提醒暂停，配置保留；重新设置对应时间后恢复。编辑器明确显示这条影响，不假装全天存在午夜提醒锚点。独立截止的相对提醒与准确时间提醒继续沿用既有规则。

“地点与备注”复用任务描述，作为普通任务备注保存，不新增平行地点实体。输入按纯文本处理，通过 DOM 的 `textContent` 构建段落，保留换行；尖括号、脚本样式文字和 `&` 不会成为可执行 HTML。仅填写备注也受到离开确认保护。

## 其他页面与同步

项目时间线将明确的全天区间计入日期覆盖，exclusive end 转成最后覆盖日；未设置日期的任务仍不虚构日期。公开忙闲页继续遵守项目授权、隐藏和别名规则，在其声明的上海时区扣除全天占用，并显示全天日期。真实区间不在公开窗口内时，仍可显示窗口内独立截止事项。

CalDAV 全天 VTODO 使用 `DTSTART;VALUE=DATE` 与整日 `DURATION`，独立的定时截止通过 `X-VIKUNJA-DUE` 保真。导入兼容 DATE DUE 和旧 DATE DTEND，但不输出 VTODO DTEND 或混合 DATE DTSTART 与 timestamp DUE。动态周期打卡提醒继续不导出成静态 VALARM；日历客户端不认识自定义截止字段时可能忽略该独立截止，本站与阿罗娜的截止语义不变。

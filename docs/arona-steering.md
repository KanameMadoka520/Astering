# 阿罗娜运行中补充要求

运行中的会话可以继续发送文字要求。新要求属于当前执行轮次，原始请求、中间回复和工具记录继续保留。停止是独立操作；离开页面或关闭浮窗不停止任务。

## 接收和执行

`POST /api/v2/ai/conversations/{id}/steer` 接收 `turn_id`、`request_id` 和 `message`。服务端按收到的顺序，将每条要求保存到所属轮次的 `steering` 中。记录包含服务器生成的 ID、原文、接收时间和状态：

- `pending`：已保存，等待执行循环在安全边界接收。
- `applied`：已保存到当前执行上下文；这不表示要求涉及的操作已经完成。

已有的权限、模型、项目范围和预算继续生效。文字要求不能改变账户授权或绕过审核。正在进行的模型请求或工具调用不能被追溯修改；执行循环在边界处理补充要求，重新考虑尚未执行的计划。先前已完成的操作仍以工具执行记录为准。因要求改变而取消的旧工具计划显示为“已跳过”，与执行失败、用户拒绝分别统计。

同一条消息重试使用相同 `request_id`，避免因网络中断重复添加。相同 ID 改发不同文字会被拒绝。新要求只能投递给当前运行中的指定轮次；如果运行已经结束，服务端拒绝新投递，前端保留草稿，供用户决定下一步。

## 历史与恢复

原始请求不因补充要求而改变。追加的要求作为独立事件保留，后续上下文、分支和导出继续包含这些内容。失败、停止或服务端中断后，尚未接收的要求仍保留在记录中，恢复执行时再处理；不会因为刷新页面自动重放已经完成的工具操作。

尚未确认送达的文字在发请求前保存到当前浏览器标签页的恢复队列，按服务器和账户隔离。连续失败逐条保留，重试继续使用原请求 ID；刷新或展开浮窗后可以恢复。已由服务器列出的要求以服务器记录为准。本地存储不可用时界面说明无法跨刷新恢复；不会覆盖后来输入的文字。

模型上下文长度和服务商可靠性仍有实际限制。保存全部原文、明确接收状态和在压缩时保留要求，可以避免程序把原始任务或追加内容静默丢弃；这不是对模型绝不会理解错误的保证。

## 时间

存储和 API 的时间保持 UTC。对话页面以及人可读的导出固定使用 GMT+8：用户消息显示发送时间，助手结束后显示实际结束时间。运行中没有完成时间时，不用页面当前时间或请求开始时间代替。缺失或无效的旧时间不生成虚构值。JSON 保留原始 UTC 时间，便于其他程序处理。

## 1Panel 站点兼容

`deploy/1panel-ai-steering-acl.json` 是本站原有 AI 规则加入 `steer` 后的完整原生规则。部署时仅更新 `task.tcymc.space` 的对应站点规则，保留 JSON POST、UUID 路径和 Bearer 头格式限制，不修改其他站点或全局规则。1Panel 的 allow 会跳过匹配请求的后续 WAF 检查；头格式匹配不代表认证成功，真实认证、会话归属、输入大小和运行状态仍由应用校验。

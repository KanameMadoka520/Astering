# Astering v2.7.1-aster.72

修复笔记保存、语音收尾和上传准备中的异步竞态，完善取消及资源回收边界。服务端与网页更新，Android 客户端继续使用 `.69`。

## 笔记与语音

- 正文保存期间收到较新版本时，在保存回执后重新核对。没有继续输入就显示较新正文；继续输入则保留草稿并提示比较版本，避免漏显示自动入文的转录，或把旧正文误标为最新已保存。这是界面状态修复，不代表已发现服务器正文丢失。
- 文件录音停止后继续检查原会话归属，最多等待 30 秒确认最终音频。浏览器编码器没有返回结束事件时，明确提示中断、释放麦克风与缓冲并允许重试，不再无限停在处理中。迟到事件不能污染下一次录音。
- 短语音运行取消后，迟到字幕不再更新聚合，排队的普通事件不再发送。已准入的底层写入使用 5 秒有界传输上下文，避免取消恰好发生在就绪消息写入期间时关闭整个连接、吞掉必要的固定错误提示。已经发送的字节不能撤回。

## 上传与可维护性

- multipart 解析、图片转换、展示文件名和发送请求之间重新检查账户、登录会话、服务器与操作归属。切换账户或清理上传后，旧操作不再重新弹出图片选项，也不继续解码后面的文件。
- 同一个上传进度行重试时，按开始顺序确定操作归属，旧解析、转换和进度回调不能覆盖新操作。临时归属在操作结束或清理时释放，正常 JWT 刷新保持有效。
- 复用现有请求上下文、笔记版本核对和录音生命周期，不新增后台轮询服务、持久业务缓存或第三方运行依赖。把准备阶段归属、保存后版本协调及录音取消规则写入后续 agent 必读的长期开发准则。
- 品牌迁移说明改为引用 README 与实际 Release，避免在多个文档里重复维护容易过期的“当前版本”。

新增竞态回归先确认未修复行为失败。后端首轮回归还暴露了底层 WebSocket 写入被取消后关闭连接的问题，修复后保留真实连接回归，未降低断言。测试使用本机隔离数据、合成音轨和模拟识别服务，不向生产笔记写入测试文字，不调用付费模型；不把这些结果当作 Android 真机或用户实际麦克风的验收。

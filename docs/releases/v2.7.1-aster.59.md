# v2.7.1-aster.59

新增项目内容历史：为重要进展保存命名保存点，查看真实差异，并在保留协作事实的前提下恢复项目内容。它与「项目时间线」的日期覆盖、完成及归档记录分别呈现。

- 项目菜单提供「项目历史版本」入口。当前有读取权限的成员可以浏览；编辑者可以保存；当前项目管理员可以恢复或删除保存点。匿名及链接分享不开放历史。
- 保存项目标题、描述、颜色和背景，任务内容与日期，视图、看板栏目及排布，公告、周期配置和正式附件引用。列表分页展示，历史正文及图片按需读取，支持桌面和手机布局。
- 恢复前显示整个计划的摘要、逐项差异、冲突与保留范围。项目在预览后发生变化时，旧确认会被拒绝，要求重新比较，不部分覆盖。
- 每次恢复在同一事务中先建立「恢复前」保存点，应用并核验完整结果，再建立恢复结果保存点。可以用同样的预览与确认流程恢复到此前内容。
- 后来新增的评论、实际打卡、周期进度、计时记录，以及当前所有者、成员和共享权限均保留。评论仍引用的任务图片继续保留正式附件关系。当前项目完成及归档状态不回滚；归档项目需要先明确取消归档。
- 目标中没有的活动任务移入回收状态，恢复前保存点保护其内容与事实。历史中仍被引用的任务及文件不会被通常的后台清理误删。已移到其他项目的任务不会被夺回；失效标签、成员和缺失原件等情况显示冲突。
- 未改变的实体按项目内内容哈希去重，新增内容压缩保存；图片和其他文件复用原件。界面分别说明内容字节、新增对象字节及引用文件大小，避免把引用大小当成重复占用。
- 保存点不自动过期。删除需要准确名称确认，只解除该保存点的引用；如果软删除任务失去全部历史保护，会恢复通常的 30 天回收清理规则，确认框说明其对评论和打卡的影响。
- 阿罗娜增加七个延迟发现的历史工具：分页查保存点、读单个版本、查实体索引、读单个实体、预览、保存及恢复。沿用「项目与任务」能力模块、当前账户资源权限和本轮项目写入范围；整项目恢复始终需要人工审核。
- 工具上下文只返回必要摘要，大量映射保留在完整审计结果中按需读取。恢复成功回执可直接进入结果保存点和恢复前保存点。界面及工具结果共用局部状态同步，不整页刷新，也不覆盖尚未提交的本地草稿。
- 普通内容写入、跨项目移动和权限变更与历史保存／恢复采用统一的事务锁顺序，等待后重查归属和当前权限。新增 API 令牌路由单独登记，已有读取权限不自动扩大为历史恢复权限。
- 修复删除项目视图后遗留看板栏目的问题；历史恢复能够识别旧版本留下、确属原项目的栏目，仍拒绝接管其他项目的视图或栏目。
- 修复 SQLite 并发刷新历史时的旧快照冲突，并通过真实 WAL 并发回归验证附件上传的写入保护。文件保存不自动重放；事务提交结果不明确时不自动重试。
- 项目菜单导航后及时收起；没有标题的布局条目显示实体标识，便于区分差异。

本功能从明确建立的保存点开始记录，不能恢复上线前或未保存的任意编辑时刻。永久删除项目也会删除它的保存点。项目历史不代替独立数据库与文件备份，不递归恢复子项目，也无法撤回已发送的通知或外部 MCP 操作。范围、存储口径和后续维护要求见[项目内容历史与恢复](https://github.com/KanameMadoka520/Astering/blob/v2.7.1-aster.59/docs/project-versions.md)。

数据库迁移仅新增六张历史表，不改写现有业务表结构或已有内容。构建、测试和发布在本机执行，GitHub Actions 保持关闭。

本机验收包括完整后端 Feature 回归（1,419 个顶层测试通过）、真实 PostgreSQL 和 MySQL 的历史与并发回归，以及最终 SQLite WAL 专项合并回归（43 个顶层与 65 个子例通过，8 个数据库条件跳过）。请求取消分类及历史接口的最后定向回归通过；后端 lint 为 0 issues。

相关前端单元测试、强制完整 TypeScript 检查及定向代码和样式检查通过。最终 Chromium 真实浏览器验收 9/9 通过，覆盖 1440px 桌面与 390px 中文手机、附件原字节下载、实际恢复、权限拒绝、过期预览、幂等重试、归档保护、分页删除，以及视图恢复后的局部导航；该轮日志没有 HTTP 500 或数据库锁错误。
